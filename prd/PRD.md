## 1 产品概述

> 反向还原：从 `doc/调率站产品与计算逻辑.md` 提炼产品定位，从实际功能反向描述现状。

### 1.1 背景

《燕云十六声》的毕业配装计算依赖社区作者维护的 Excel 计算器（Violetta@片雲 及各流派表作者）。这些工作簿功能强但使用门槛高、结果不可保存、词条组合难以复用。调率站把 Excel 的数值逻辑固化成浏览器可运行的计算引擎，并叠加了装备档案、方案管理和培养决策能力。

### 1.2 产品定位

调率站是一套**装备档案、配装分析和培养决策工具**。它主要回答四个问题：

1. 当前角色的完整配装形成了怎样的最终面板？
2. 这套面板在指定流派的标准输出方式下能产生多少伤害？
3. 当前输出距离该流派的理论毕业水平还有多远？
4. 更换、培养或转律哪些装备最值得？

### 1.3 价值主张

| 维度 | 价值 |
| --- | --- |
| 计算结果 | 与社区 Excel 计算器同口径（随上游更新），本地浏览器运行，隐私友好 |
| 数据留存 | 装备档案、配装方案、转律状态本地保存，可完整备份与云端同步 |
| 决策辅助 | 从"看毕业率"进阶到"怎么提升"，提供词条收益、培养、转律、最佳配装 |
| 低门槛录入 | 手动录入 + 截图 OCR + 批量 OCR 三种录入方式 |

### 1.4 核心逻辑链

```text
装备配置
  ↓
最终面板
  ↓
指定流派输出模拟
  ↓
当前 DPS
  ↓
与理论毕业 DPS 比较
  ↓
毕业率
```

这条链路也是词条收益、培养建议、单件装备比较和最佳配装的共同基础。

### 1.5 现状盘点（已具备的能力）

- **计算引擎**：Q7 原版引擎（跟随 `yysls.leoq7.com`，仅赛季抗性本地覆盖为 2.45）。
- **装备管理**：多角色、八槽位穿戴、装备等级（110/105/100/96）、承音、紫装、可转律资格、可用流派限制、词条录入。
- **毕业率分析（六标签）**：手动填写表格（含按词条数量/直接填面板双模式）、最佳配装、词条优先级、培养建议、转律建议、单件装备对比。
- **方案管理**：每角色每流派每版本最多 50 套命名方案，含转律覆盖层（非破坏性）。
- **数据能力**：完整 JSON 备份/恢复、单角色导入导出、云端备份（Supabase）、Excel 填表下载。
- **OCR**：单件截图识别 + 批量 OCR 导入。

### 1.6 产品愿景

> 让每个玩家都能用最低的录入成本，把"我穿什么"准确换算成"我毕业了多少、还差什么、怎么提升"，并把社区 Excel 的数值权威固化成一个可用、可存、可对比的日常工具。

### 1.7 现状局限（反向盘点中暴露的问题）

- 首页首屏可能出现"毕业率 0.00%"占位后再刷新为真实值（异步 WASM 就绪前的降级显示）。
- 产品定位名为"自用"，但实际对外可访问，品牌与帮助文案存在定位模糊。
- 依赖上游数值更新节奏，新版本跟进时效受社区发布约束。

## 2 用户与场景

> 反向还原：从功能布局与"自用装备管理台"定位推断用户画像；从 `index.html` 交互入口还原使用场景。

### 2.1 用户画像

#### 核心用户：深度配装玩家

- 玩《燕云十六声》，追求流派输出上限；
- 愿意投入时间刷装备、承音、定音、转律；
- 会关注社区计算器（Excel 表、B站作者）来规划毕业配置；
- 需要"我的装备到底什么水平、还差什么"的量化答案。

#### 边缘用户

- **新手中度玩家**：刚接触毕业率概念，需要"计算中…"等加载反馈与结果解读引导。
- **多角色玩家**：多个角色、多套方案，需要数据隔离与快速切换。
- **多设备玩家**：电脑录装备、手机查结果，需要云端备份与冲突保护。

### 2.2 典型使用场景

| # | 场景 | 用户目标 | 主要入口 |
| --- | --- | --- | --- |
| S1 | 首次录入装备 | 把手头八件装备快速建档 | 录入装备（手填 / OCR / 批量 OCR） |
| S2 | 查看当前毕业率 | 知道"我现在毕业了多少" | 主页毕业横幅（流派/表格/武库/心法/弓诀/套装） |
| S3 | 手动规划理想面板 | 不看实际装备，模拟"词条数量→毕业率" | 毕业率分析 → 手动填写表格 |
| S4 | 搜索最佳配装 | 从仓库里找出毕业率最高的八件组合 | 毕业率分析 → 最佳配装 |
| S5 | 分析词条优先级 | 知道接下来刷哪条词条收益最大 | 毕业率分析 → 词条优先级 |
| S6 | 获取培养建议 | 逐件装备"改什么最值得" | 毕业率分析 → 培养建议 |
| S7 | 转律决策 | 某件 110 级装备是否值得转律、转哪条 | 毕业率分析 → 转律建议 |
| S8 | 单件装备对比 | 候选装备放进当前配装里比较强弱 | 毕业率分析 → 单件装备对比 |
| S9 | 多方案管理 | 同一角色保留多套配装思路 | 面板 → 方案（新增/改名/删除） |
| S10 | 数据备份迁移 | 换设备/清浏览器不丢数据 | 导出/导入 → 完整备份；云备份 |
| S11 | 下载填好的 Excel | 把当前配装回填到社区计算表存档 | 下载填好的表格 |

### 2.3 用户故事（As a…I want…）

- 作为玩家，我希望首页直接显示当前毕业率，以便快速了解现状 → 主页毕业横幅。
- 作为玩家，我希望手动模拟"我刷到多少条某种词条"能立刻看到毕业率，以便规划培养 → 手动填写（按词条数量）。
- 作为玩家，我希望在转律前知道哪个副词条最值得转，以便不浪费资源 → 转律建议。
- 作为玩家，我希望最佳配装能区分"已转律/待转律/不考虑转律"，以便贴近我的真实资源 → 最佳配装三模式。
- 作为多角色玩家，我希望每个角色的装备、方案、转律状态互不干扰 → 角色级数据隔离。
- 作为换机用户，我希望一个 JSON 文件能完整恢复所有角色与方案，以便无缝迁移 → 完整备份/恢复。
- 作为多设备用户，我希望云端备份不要静默覆盖另一台设备的更新，以便数据安全 → 云备份冲突保护。

### 2.4 用户心智模型

用户把产品理解为三件事的串联：

1. **我的装备档案**（录入 → 仓库 → 穿搭）；
2. **我的毕业度量**（面板 → DPS → 毕业率）；
3. **我的提升路径**（词条收益 → 培养 → 转律 → 最佳配装）。

因此产品的信息架构与文案都应围绕"档案 / 度量 / 提升"组织，避免把技术名词（WASM、引擎、flowName）暴露给用户。

### 2.5 关键假设（待验证）

- 用户愿意为"正确性"牺牲首屏速度（接受异步加载后的刷新）；
- 大多数用户只关注当前流派，跨流派功能属于深度场景；
- 用户信任数值来自社区作者，理解"结果随上游版本变化"。

## 3 核心流程

> 反向还原：从 `doc/调率站代码实现说明.md` 与运行时行为还原关键流程；强调"所有分析入口必须复用同一计算链"。

### 3.1 主计算数据流

所有常规毕业率入口（主页、手动面板、词条收益、培养建议、转律建议、单件比较、最佳配装）统一走：

```text
页面/分析功能
  ↓
统一 options（equippedItems, className, flowName, flowVersion, bow, xinfa, setName, armory,
             赛季/PVP, 贷款定音, classInputOverrides, 转律覆盖后的装备）
  ↓
YYSLSExcelRuntime.calculate()
  ├─ calculatePanel()   ← Q7 单体 WASM（yysls_calc_diy）：配置 → 最终面板
  └─ collectBonuses()   ← 定音/穿透/武器增效/奇术增伤/临时修正
       ↓
calculateFromPanel()
  ↓
Q7 单体 WASM（yysls_calc_class_outputs，40项输入 → 5项输出）
  ↓
totalDamage / DPS / graduationRatio / RDPS / RDPS 毕业率
```

**硬约束**：任何分析入口不得自行复制一套简化毕业率公式，否则会与主页和最佳配装产生口径分叉。

### 3.2 启动与首屏

```text
页面加载
  ↓
加载 Q7 引擎字符串/元数据/应用配置/运行时与 best40-stats
  ↓
加载 assets/wasm/q7/yysls_calc.wasm
  ↓
app.min.js init() → 恢复最近角色 → 加载该角色当前流派方案 → updateStats()
  │
  ├─ WASM 未就绪 → 降级显示 0.00% / "计算中…"
  ├─ Panel WASM 就绪 → 立即预加载当前 flowName 的 Excel WASM → 重算
  └─ Excel WASM 就绪 → 显示真实毕业率
```

### 3.3 毕业率分析流程（六标签统一入口）

```text
毕业率分析弹窗
  ├─ 手动填写表格：构造/分配面板 → 统一计算链 → 展示毕业率
  ├─ 最佳配装：仓库候选 → 过滤 → 预编译 → 批量计算 → Top20 → 去重 → 复核
  ├─ 词条优先级：当前配置 ± 目标词条 → 差值排序
  ├─ 培养建议：逐部位模拟词条/定音改善 → 边际收益排序
  ├─ 转律建议：替换指定副词条 → 遍历合法目标 → 完整配装毕业率对比
  └─ 单件装备对比：替换单槽位 → 其余环境不变 → 重算 → 排序
```

### 3.4 最佳配装搜索流程

```text
按部位构造候选装备（应用流派/武器/实体互斥/词条数量/面板阈值）
  ↓
根据模式生成候选（不考虑转律 / 优化已转律 / 同时规划待转律）
  ↓
预编译装备（rawEntries / bonusEntries / 穿戴状态 / 品质）
  ↓
批量 calculateBestBuildCompiled()，以毕业率维护候选堆
  ↓
生成 Top20
  ↓
最终复核、去重（八件原始装备 ID + 承音状态）、展示
```

关键不变量：

- 同一件物理装备不能同时占据两个槽位（`getOriginalEquipId` 归并转律副本）；
- 缓存摘要必须包含流派环境、弓诀、限制、转律模式；
- 转律通过非破坏性覆盖层（`transmutationSelections`）参与计算，不修改装备库原对象；
- 取消搜索需终止后续批次与结果写入。

### 3.5 转律建议流程

```text
选择左侧装备部位
  ↓
待转律装备：遍历所有副词条 → 找最值得指定的槽位与目标
已转律装备：只分析状态中指定副词条 → 不允许算法改换槽位
  ↓
保持其余七件与环境不变，按当前流派/弓/套装/心法/赛季/贷款定音实时计算
  ↓
输出最佳目标、最终毕业率、相对原词条差值
```

### 3.6 数据备份与恢复流程

```text
完整备份（导出）：
  全部角色 + 每角色装备(保留ID) + 全部流派方案 + 转律状态 + 手动毕业率数据
  → 单个明文 JSON（格式 yysls-tiaolv-full-backup, schemaVersion:2，不含可重建缓存）

完整恢复（导入）：
  校验格式/版本/结构/装备引用 → 汇总预览（角色数/装备数/方案数/同名角色）
  → 确认 → 按角色覆盖并保留未含本地角色 → 失败回滚

云备份（Supabase）：
  localStorage 为即时源 → 变更后 1 分钟单向上传（SHA-256 去重）
  → 上传前比较本地哈希/上次基线/当前云端哈希 → 发现他设备更新则暂停并询问
  → 恢复/上传前保护快照 → 恢复成功才写入新基线
```

### 3.7 计算引擎

```text
固定加载 Q7 原版引擎（yysls.leoq7.com）
  ↓
启动即加载 assets/wasm/q7/yysls_calc.wasm、元数据、字符串与运行时
  ↓
无引擎切换入口，无跨引擎回退/混用
```

## 4 功能需求

> 反向还原：按 `index.html` 页面结构与交互入口盘点六大功能模块；每条给出验收标准。
> 需求层级：`必须` = 现状已具备且必须长期保留；`增强` = 现状已有但可优化；`建议` = 反向盘点中提出的演进方向。

### 4.1 装备管理

| 功能 | 需求 | 验收标准 |
| --- | --- | --- |
| 角色管理 | 必须 | 可新建/重命名/删除角色；删除需二次确认；角色级数据完全隔离 |
| 装备录入 | 必须 | 八槽位；主词条 1 + 副词条 4 + 定音 1；数值精度 0.01；品质金/紫 |
| 副词条满值 | 必须 | 四条副词条的满值按钮均可用；词条刷新或转律控件注入后不丢失事件；承音期间禁用、取消承音后恢复 |
| 装备等级 | 必须 | 115/110/105/100/96 级；缺省旧数据按 105 处理；卡片显示等级标签 |
| 承音 | 必须 | 承音=把低等级装备升级到高等级；承音只由「承音」复选框决定，不按数值反推；115 级且勾选显示「承音」（绿），低于 115 级显示「需承音」（橙）；承音值参与"培养后"口径计算；详见 [11.3](#113-等级与承音) |
| 紫装 | 必须 | 紫装基础攻击差值（武器/环/佩）参与计算 |
| 可转律资格 | 必须 | 仅 110 级且勾选可转律可进入转律；非 110 级隐藏并清除该资格 |
| 编辑草稿保护 | 必须 | 点击装备编辑弹窗遮罩空白处时询问是否保存；确认复用正常保存校验，拒绝则丢弃草稿；不影响关闭/取消按钮既有行为 |
| 可用流派限制 | 必须 | 多选限制装备可用流派；武器位置按武器规则禁用不兼容流派 |
| 词条来源合法性 | 必须 | 词条必须符合部位词条池与数量上限（详见 5.5） |
| OCR 识别 | 必须 | 截图识别词条并回填表单；识别结果需用户确认 |
| 批量 OCR | 必须 | 粘贴外部工具结果，一次导入多件装备 |
| 自动命名 | 必须 | 录入/修改弹窗一键按主词条+副词条缩写自动命名；缩写体现词条，三率前置、增效置后，相同词条数量前缀（如 `2大外`）；手动输入优先不被覆盖。当前角色左侧提供「全部重命名」按钮，经二次确认后一键重命名当前角色全部装备。新增装备保存时若未手动命名、以及批量 OCR 保存的装备，均默认按词条自动命名 |
| 装备库排序/过滤 | 必须 | 等级降序 + 品质 + 承音 + 首词条种类排序；可用/全流派开关 |

### 4.2 面板配置

| 功能 | 需求 | 验收标准 |
| --- | --- | --- |
| 流派选择 | 必须 | 10 个 PVE 流派；切换触发重算 |
| 表格版本选择 | 必须 | 每流派可切换版本（如牵丝翊 1.2/2.0）；版本决定计算口径 |
| 武库选择 | 必须 | 按流派给出武库选项 |
| 心法选择 | 必须 | 四本心法；可更换并提示不支持的心法 |
| 弓诀选择 | 必须 | 精准/会心/会意弓 |
| 套装选择 | 必须 | 套装静态属性进入面板 |
| 赛季开关 | 必须 | "提前获得下半赛季属性"；开启后毕业率虚高提示 |
| PVP 开关 | 必须 | "首领视为玩家"；改变面板与词条池显示 |
| 贷款满定音 | 必须 | 勾选后按假设满定音参与计算，与真实定音区分口径 |
| 面板校验提示 | 必须 | "面板不对？"入口给出排查指引 |

## 7 边界与非目标

> 反向还原：从 `doc/调率站代码实现说明.md`、`doc/tiaolv-local-customizations.md` 提炼的红线与明确不做的事。

| 不做 | 原因/依据 |

| 红线 | 说明 |

```text
计算引擎（Q7 原版单体 WASM）
  └─ assets/wasm/q7/yysls_calc.wasm（面板 + 伤害/毕业率）
```

### 7.4 已移除功能的永久性

- **转律 CD**：入口、运行时、存储、备份字段均不存在；保留一次性历史数据清理迁移。

## 11 业务逻辑细则

> 本章把调率站的全部业务逻辑逐条固化为可审查规则，作为数值核对、回归测试和上游同步的判据。
> 规则描述**现状实现**；标注「红线」的条目不得被上游同步覆盖（见 [5.4](#54-本地定制层必须长期保留)）。
> 相关实现见 `doc/调率站代码实现说明.md`、`doc/调率站产品与计算逻辑.md`、`doc/转律机制说明.md`。

### 11.1 数据模型与本地存储

| 实体 | 字段 |
| --- | --- |
| 角色 | 数据隔离单元；列表存 `game_account_list` |
| 装备 | 稳定 ID、部位、名称、武器类型、等级、品质（金/紫）、承音、可转律、可用流派、主词条、四条副词条、定音 |
| 配装方案 | 八槽位穿戴 + 弓诀 + 套装 + 心法 + 武库 + 版本 + 赛季/PVP/贷款定音 + `transmutationSelections` 覆盖层 |
| 转律状态 | `zhuanlv_status_<account>`：槽位记录 `{state, subStatIndex, modelVersion}` |
| 手动毕业率配置 | 按角色/流派/版本保存，含词条数量模式与组合预设 |

| 本地存储 Key | 内容 |
| --- | --- |
| `game_account_list` | 角色列表 |
| `game_equip_data_<account>` | 装备仓库 |
| `game_sim_data_<account>` | 配装、方案、计算选项 |

- `getDB()` 读取后统一执行规范化：缺失等级按 `105`；低于 110 级清除 `isTransmutable`；承音装备的承音词条值按承音值补齐。

### 11.2 装备录入与校验

**槽位**（`slotId`）：1 武器（`weapon1`/`weapon2`）、3 环、4 佩、5 冠胄、6 胸甲、7 胫甲、8 腕甲。每件装备 = 主词条 1 + 副词条 4 + 定音 1；数值精度 0.01。

**词条合法性**（详见 [5.5](#55-词条来源与合法性业务约束)）：
- 总容量 8 主 + 32 副 = 40 条普通词条；定音额外不占名额；
- 首领增伤仅胫甲/腕甲、整套 ≤2；全武学增效仅环/佩、整套 ≤2；单体/群体奇术增伤仅冠胄/胸甲、各 ≤2；武器武学增效绑定武器；
- 同件装备不能有两个相同副词条；主词条可与一个副词条同名。

**金装与紫装基础攻击差值**（已在 Panel WASM 内计算，JS 不再事后扣减）：

| 部位 | 金→紫差值 |
| --- | --- |
| 武器 | 最小外功 -10、最大外功 -23（金 100/232，紫 90/209） |
| 环 | 最小外功 -13（金 133，紫 120） |
| 佩 | 最大外功 -20（金 199，紫 179） |

**自动命名**：按主词条 + 副词条缩写生成；三率前置、增效置后、相同词条加数量前缀（如 `2大外`）；手动输入优先不被覆盖；新增保存未命名时、以及批量 OCR 保存时默认自动命名；「全部重命名」经二次确认后重命名当前角色全部装备。

**重复装备**：录入时若数据库中已有相同词条类型的装备，比较品质百分比，自动保留更高者并提示。

**可用流派**：多选限制；武器位置按 `ClassConfig.WEAPON_RULES` 禁用不兼容流派；`pvp` 仅作为标签，不进入任何计算。

### 11.3 等级与承音

**等级**：`115 / 110 / 105 / 100 / 96`，缺省旧数据按 `105`。等级颜色：115 红、110 橙、105 蓝、其他灰。

**承音定义（红线）**：

> **承音 = 把低等级装备升级到高等级的能力／结果。一件「承音装备」是原本低等级、经承音升上来的装备，不是原生当前等级的装备。**

承音记录与显示规则：

| 规则 | 说明 |
| --- | --- |
| 判定来源 | **只由装备录入的「承音」复选框决定**；不得依据词条数值反推（旧版按数值判定已废弃） |
| 115 级 + 勾选承音 | 显示绿色「（承音）」，为真实承音装备 |
| 等级 < 115 | 一律显示橙色「（需承音）」，表示尚需承音升级（无论是否勾选） |
| 115 级未勾选 | 原生 115 级，不显示承音标签 |
| 承音版（系统生成） | 最佳配装为未承音/低质量装备生成的升级版，id 含 `_chengyin`，显示「（需承音）」 |

**承音值**：`generated-calc-metadata.js → chengyinValues`；缺失该词条时回退 `roundStatValue(0.94 × MAX_VALUES)`（`getChengyinValue`）。勾选承音或应用承音版时，把主词条与四条副词条按承音值补齐（`normalizeChengyinEquip`）。

**承音版生成**（`createChengyinVersion`）：深拷贝原装备，id 追加 `_chengyin`，置 `isChengyin = true`，并把词条值改为承音值；不修改装备库原对象。

**需承音计数**（`countNeedChengyin`，用于「最多需要承音」筛选）：

```text
需要承音的件数 = 方案中 (id 含 _chengyin) 或 (等级 < 115) 的装备数量
```

即低于 115 级必须计入（必须承音升级）；真实 115 级承音装备不计入。

### 11.4 转律

**资格**：仅等级 ≥110 且显式勾选「可转律」的装备可转律；承音与紫装不影响资格；<110 级隐藏勾选框并清除资格。完整规则以 `doc/转律机制说明.md` 为准：

- 只作用于一个副词条槽位；已指定后不可改槽；
- 候选来自全部武库合并去重；当前流派只保留对应属性攻击；
- 武器候选永久排除最大鸣金/裂石/牵丝/破竹攻击，并确保包含最大无相攻击；
- 替换后同件副词条不得重复；原词条始终是合法候选；
- 状态三态：不可转律 / 待转律（`isTransmutable` 且无有效槽位）/ 已转律（槽位记录）；
- 转律模拟词条使用理论承音值；贷款定音与转律相互独立；
- 已删除：转律 CD 提醒、旧「指定转律目标」入口、旧等级转律规则。

### 11.5 从装备配置到最终面板

统一入口 `YYSLSExcelRuntime.calculate()`，所有入口（主页/手动/收益/培养/转律/比较/最佳配装）必须复用同一输入口径。

```text
统一 options
  → calculate()
      ├─ calculatePanel()：buildDiyRaw() → Q7 单体 WASM(yysls_calc_diy) → panelFromArray() → 三率溢出/增伤标记
      └─ collectBonuses()：定音、穿透、武器增效、奇术增伤、临时修正
          → calculateFromPanel() → yysls_calc_class_outputs → totalDamage/dps/graduationRatio/rdps
```

**基础面板叠加**：

```text
公共裸角色属性 + 所选流派武学与天赋 + 四心法 + 八槽位固定属性与调音词条 + 套装/弓诀/武库 + 敏/势/劲派生 + 抗性换算
```

- 裸角色基准：最小外功 `930`、最大外功 `1688.4`、敏/势/劲各 `283`、原始精准 `110.1%`、原始会心 `24%`、原始会意 `12%`、无相 `79.2~92.4`、等级抗性 `2.45`、增益抗性 `1.15`；
- 派生公式：

| 派生 | 公式 |
| --- | --- |
| 最小外功派生 | `0.9 × 敏 + 0.22 × 劲` |
| 最大外功派生 | `0.9 × 势 + 1.36 × 劲` |
| 会心派生 | `0.076 × 敏` |
| 会意派生 | `0.038 × 势` |

- 装备来源的武器增效/奇术增伤/首领增伤/全武学增效先汇总，再除以增益抗性 `1.15`；
- 三率上限与溢出：精准 `100%`；会心基础 `80%`（部分流派/套装调整）；会意 `40%`；会心/会意还受组合上限；裂石钧存在「钧钧」联动阈值；溢出白值不能由「显示值 − 上限」反推；
- 可计算流派固定 10 个 PVE 流派；`pvp` 不进入计算；
- Panel 输入前缀 184 项配置/词条兼容，内部追加 18 项装备结构信息，共 202 项；公开 API 与存档格式不变。

### 11.6 流派输出与毕业率

- 每个流派/表格版本使用独立 Excel WASM：40 项 `f64` 输入，输出顺序 `totalDamage → dps → graduationRatio → rdps → rdpsGraduationRatio`；
- 毕业率优先用 `graduationRatio × 100`，否则回退 `dps ÷ baselineDps × 100`；
- 基准优先取 `generated-calc-metadata.js → classRotationStats`，回退旧 `ClassConfig.ROTATIONS`；
- 100% 基准面板来自 `flowGraduationProfiles[flowName]`（Excel 标准输入区），仅用于展示与解释，不替代用户当前面板；
- DPS = 一轮期望总伤害 ÷ 输出轴时间；毕业率 = 当前 DPS ÷ 理论毕业 DPS × 100%；
- 超过 100% 不一定是错误（可能使用了不同于基准的心法/套装/环境）。

### 11.7 最佳配装

**算法**：`YYSLSBestBuildAlgorithms` 注册 `legacy-exhaustive`（默认，精确遍历）与 `genetic-optimizer`（智能遗传搜索，近似）。流程：构造按部位候选 → 应用限制 → 按模式生成转律候选 → 预编译 → 批量计算 → 维护候选堆 → Top20 → 复核去重展示。

**候选生成规则（关键）**：

| 装备状态 | 参与候选 |
| --- | --- |
| 已勾选承音 | 原样参与（真实承音装备） |
| 等级 < 115 未承音 | 只生成 `_chengyin` 承音版（需承音升级） |
| 等级 = 115 未承音，质量 < 0.92 | 只生成承音版 |
| 等级 = 115 未承音，质量 0.92~0.96 | 原装 + 承音版都参与 |
| 等级 = 115 未承音，质量 ≥ 0.96 | 只用原装 |

其中 `BEST_BUILD_MAX_EQUIPMENT_LEVEL = 115`；质量 = 主/副词条值 ÷ 最大值的平均（`getEquipAveragePercent`）。

**不变量**：

- 八部位完整、武器与流派匹配；
- 同一物理装备（原装/承音版/转律变体，按 `getOriginalEquipId`）互斥，不能占两槽；
- 转律三模式：不考虑转律 / 只优化已转律 / 同时规划待转律；模式按角色记忆；
- Top20 按「八件原始装备 ID + 各自是否需承音」去重，转律目标不进去重键；
- 限制：最多需承音件数、主/副词条条数、面板上下限；搜索使用相同心法/套装/武库/赛季/输出轴；
- 取消搜索需终止后续批次与结果写入。

**应用方案（`applyBuild`，红线）**：只改写 `AppState.equippedItems` 与 `transmutationSelections` 覆盖层，不修改装备库原对象。方案件为承音版（id 含 `_chengyin`）时，把数据库对应装备按承音值套用后再穿戴，保证模拟器结果与搜索结果一致。

### 11.8 围绕毕业率的分析功能

| 功能 | 逻辑 |
| --- | --- |
| 手动填写表格 | 双模式：按词条数量（数量 → 8 件理论装备合法分配，8 主/32 副/40 普通上限）或直接填面板；满值/承音值两种口径；词条修正项不占数量；组合预设每角色每流派每版本 ≤50 套 |
| 词条优先级 | 控制其他不变，增加/移除目标词条后重算，输出 `收益 = 加后 − 当前`、`损失 = 当前 − 移除后` |
| 培养建议 | 固定其余七件与环境，枚举当前部位合法主词条与四副词条满值组合，选毕业率最高的一组；按（替换后 − 当前）排序；展示 100% 基准面板 |
| 转律建议 | 待转律遍历所有副词条槽位 × 全部合法目标；已转律只分析指定槽位；只替换当前部位，其余不变 |
| 单件装备对比 | 只替换一个槽位；默认冻结当前定音；可选「假设满承音」；按替换后毕业率排序 |

所有分析入口必须复用 [11.5](#115-从装备配置到最终面板)/[11.6](#116-流派输出与毕业率) 的统一计算链，不得自带简化公式。
