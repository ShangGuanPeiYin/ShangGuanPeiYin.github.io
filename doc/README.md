## 状态与证据

用户确认的规则是产品目标，不意味着现有软件已经实现。实现状态分为“已实现（静态核对）”“存在差异”“待核实”；验证状态另列为“仅静态核对”“现有测试覆盖”“本次通过”“本次未验证”。测试文件存在不等于本次运行通过，字符串检查通过不等于浏览器行为通过。

规则使用 `GDD-*` 编号，需求使用 `SRS-*`，验证场景使用 `V-*`。编号保持稳定，不因章节排序变化而重编号。GDD 定义术语，SRS 定义软件响应，SDS 描述实际实现；其他文件引用它们，避免复制公式。

业务冲突以用户确认的口径为目标；代码说明现状；历史文档与旧 Excel 提供参考。未确认的游戏事实、外部服务配置、性能与数值正确性不得推断为已验证。已确认但未实现的行为集中在 SRS 差异表，本轮不修改代码来消除差异。

## 更新规则

- 游戏机制或计算假设变化：更新 GDD，并检查 SRS 的引用与验收条件。
- 功能行为变化：更新 SRS；实现完成后更新 SDS、差异表和验证记录。
- 存储、兼容或模块边界变化：更新 SDS 的契约和迁移说明。
- 上游同步：先读定制清单与项目规则，再使用项目 Q7 更新技能。
- 每次项目修改追加修改日志；不得把历史通过记录当作新版本验证结果。

历史资料来自本基线提交中的旧产品逻辑、转律、实现、维护和 PRD 文件。它们在工作区已有删除，未恢复；本目录用新职责重新组织内容。旧资料中的双 WASM、旧备份版本、已过时参数及旧恢复语义没有直接沿用。
