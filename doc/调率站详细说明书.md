## 一、项目概述与架构

### 1.1 调率站是什么

**调率站**（又称“自用装备管理台”）是一个完全在浏览器前端运行的《燕云十六声》装备分析与毕业率计算工具。它的核心链路可以概括为：

```
装备录入 → 本地持久化 → 面板模拟 → WASM/Excel 计算 → 毕业率输出 → 优化建议
```

所有装备数据、角色数据、方案数据均保存在浏览器 `localStorage` 中，**不上传到任何服务器**。

### 1.5 数据持久化模型

所有数据使用 `localStorage`，按账号（角色）隔离：

| Key | 含义 | 示例 |
|-----|------|------|
| `game_account_list` | 角色名 JSON 数组 | `["角色A","角色B"]` |
| `game_equip_data_<account>` | 某角色装备库数组 | `game_equip_data_角色A` |
| `game_sim_data_<account>` | 某角色面板/方案/配置 | `game_sim_data_角色A` |
| `last_selected_account` | 上次选中角色 | `"角色A"` |
| `best40StatsCache` | 最佳40词条缓存 | 对象，按 key 缓存 |
| `zhuanlv_status_<account>` | （本站定制）转律状态 | `zhuanlv_status_角色A` |
| `grad_manual_form_v2_<account>_<class>_<flow>` | 手动填写表格缓存 | 每个流派版本独立 |

### 1.6 账号（角色）生命周期

- **创建**：`submitNewAccount()` 向 `game_account_list` 追加角色名，并自动切换（`handleSwitchAccount`）。
- **切换**：`handleSwitchAccount()` 设置 `AppState.currentAccount`，持久化 `last_selected_account`，加载装备库与面板状态。
- **重命名**：`handleRenameAccount()` 遍历 `localStorage`，把该账号相关的所有 key 替换为新名。
- **删除**：`handleDeleteAccount()` 从 `game_account_list` 移除，并删除对应的 `game_equip_data_*`、`game_sim_data_*` 以及 `grad_manual_form_*` 缓存。

## 二、核心数据模型

### 2.1 装备（Equip）数据结构

每件装备在内存与存储中都是一个对象：

```js
{
  id: 1234567890,                // 时间戳生成，唯一
  slotId: "1",                   // 1=武器 3=环 4=佩 5=冠胄 6=胸甲 7=胫甲 8=腕甲
  slotName: "武器",              // 显示名称
  weaponTypeId: "1",             // 仅武器有效：1=剑 2=枪 3=伞 4=扇 5=绳标 6=双刀 7=陌刀 8=横刀 9=拳甲 10=鼓
  name: "我的剑",
  isChengyin: false,             // 是否承音（词条接近满值）
  isPurple: false,               // 是否紫装
  level: 105,                    // 装备等级（本站定制字段）
  availableClasses: ["鸣金虹", "鸣金影"], // 可用流派限制
  mainStat: { type: "最大外功攻击", value: 105.6, isPercent: false },
  subStats: [
    { type: "劲", value: 72.2, isPercent: false },
    { type: "会心率", value: 12.2, isPercent: true }
  ],
  dingyinStat: { type: "外功穿透", value: 16.8, isPercent: true } // 可能为 null
}
```

### 2.2 装备规范化流程

数据从 `localStorage` 读出后，会经过 `normalizeChengyinEquip`（未展示的底层函数）和 `restoreEquipData` 等流程：

- `restoreEquipData`（`app.min.js:5657`）：给装备补充 `slotName`、规范化 `availableClasses`、补全 `isPercent` 标志、生成缺失 `id`。
- `fixOcrPercentBug`（`app.min.js:5246`）：启动时遍历所有账号装备库，修正 OCR 可能导致的百分比类型错误。
- `getDB`（`app.min.js:5231`）：读取当前账号装备库，并给每件装备默认 `level = 105`（兼容旧数据）。
- `saveDB`（`app.min.js:5239`）：保存时统一调用 `normalizeAvailableClassesForEquip` 规范化可用流派。

### 2.5 套装、弓诀、武库

- 套装：`CommonData.SET_DATA`（`app.min.js:15`）预定义了 10 套套装及其属性加成，如 `玉斗` 加最大外功攻击、`飞隼` 加会意率等。
- 弓诀：固定三种 `precision`（精准弓）、`crit`（会心弓）、`intent`（会意弓）。
- 武库：`通用/鸣金/裂石/牵丝/破竹`，影响转律池与部分计算逻辑。

### 2.6 词条与数值上限

词条 100% 满值在 `CommonData.MAX_VALUES`（`app.min.js:47`），由 `generated-calc-metadata.js` 中的 `maxValues` 通过 `applyExcelMaxValues`（`app.min.js:472`）在启动时覆盖更新。

承音值（94%）来自 `YYSLS_CALC_METADATA.chengyinValues`，读取函数为 `getChengyinValue`（`excel-runtime.js:268`）。

百分比词条判定集合：`CommonData.PERCENT_STATS`（`app.min.js:86`），包含所有“率、加成、增效、增伤、增疗、穿透”类词条。

主词条可选范围：`CommonData.MAIN_STAT_RULES`（`app.min.js:168`）。

定音词条可选范围：`CommonData.DINGYIN_RULES`（`app.min.js:177`）。

副词条基础池：`CommonData.BASE_SUB_STATS`（`app.min.js:87`），录入时按部位再扩展武器专属、奇术增伤、对首领增伤等。

转律池：`CommonData.TRANSMUTATION_POOLS`（`app.min.js:188`），按流派武库区分可转出的词条。

### 2.7 装备词条的部位可实现性

一套完整配装由 8 件装备组成，每件装备按 1 条主词条和 4 条副词条计，因此“按词条数量”模型使用 **40 条普通词条**作为总量上限。这个总量约束只能回答“总共能放多少条”，不能回答“某一种词条实际上能出现几次”。

数量模式会把用户填写的总数量还原为真实的 8 个首词条位和 32 个副词条位。首词条遵守部位池；副词条遵守天然词条池，同一种词条在同一件装备上最多出现一次，但允许同件装备首、副词条相同。转律不作为额外来源。

首词条来源为：大小外攻可在两件武器、环、佩；三率可在冠胄、胸甲、胫甲、腕甲；劲可在两件武器、胫甲、腕甲；敏、势和无相攻击只可在两件武器。没有首词条来源的属性只能占副词条。

特殊副词条来源为：武器增效只能在对应武器；全武学增效只能在环、佩；单体/群体奇术增伤只能在冠胄、胸甲；对首领增伤和对玩家增效只能在胫甲、腕甲。

多种属性会共同争夺相同首词条部位，必须联合校验。例如大外 11 条需要 8 个副词条和至少 3 个首词条；此时四个共享攻击首词条位只剩 1 个，因此小外最多 9 条，而不是也能堆到 11 条。

## 三、主界面功能详解

### 3.1 角色管理

页面右上角提供角色下拉框、改名、删除、新建按钮。

- `loadAccounts`（`app.min.js:5985`）：启动时读取 `game_account_list`，恢复上次选中角色。
- `showWelcomeMessage` / `showEmptyEquipMessage` / `showMainContent`：根据是否有角色、是否有装备切换三种页面状态。

### 3.2 装备库

左侧主区域以卡片网格展示装备。核心函数：

- `UIManager.renderLibrary(equips, handlers)`（`app.min.js:979`）：渲染全部装备卡片。
- `filterDB(db)`（`app.min.js:6126`）：按当前筛选条件（全部/穿着/某部位/某武器类型）过滤，并叠加“可用/全流派”切换。
- `sortDB(db)`（`app.min.js:6107`）：按等级、品质、主词条类型排序。
- `initFilters`（`app.min.js:6168`）：初始化顶部的胶囊筛选按钮。

装备卡片显示：

- 装备名称、部位、等级标签（如 `[110]`）
- 平均品质百分比（非承音装备）
- 主词条、副词条、定音词条
- 承音/紫装标识
- 若已穿戴，显示装备 badge
- 编辑/删除按钮

### 3.3 装备录入弹窗

点击“录入装备”打开弹窗，表单字段联动逻辑：

- `handleSlotChange`（`app.min.js:5873`）：切换部位时显示/隐藏武器种类、重设主/副/定音选项。
- `handleWeaponTypeChange`（`app.min.js:5882`）：切换武器类型时更新副词条选项（加入该武器专属武学增效）。
- `populateSubStatsSelect`（`app.min.js:5892`）：根据部位动态构建副词条下拉列表。
- `updateAvailableClassesOptions`（`app.min.js:5909`）：构建可用流派多选下拉。
- `handleChengyinChange` / `applyChengyin`（`app.min.js:5966`）：勾选承音后，自动把所有主/副词条填为承音值。
- `updateQualityDisplay`（`app.min.js:1222`）：输入数值时显示品质百分比，异常值标红。
- `handleSaveEquip`（`app.min.js:5749`）：保存时做重复检测、紫装/承音处理、自动穿戴等。
- `findDuplicateEquip`（`app.min.js:5719`）：检测同部位同主词条同副词条类型集合的重复装备，提示保留品质更高者。

### 3.4 面板模拟器

右侧 8 槽位区域：

- 点击空槽位或已装备槽位触发 `unequipItem`（`app.min.js:6209`）卸下。
- 点击装备库卡片触发 `handleEquipItem`（`app.min.js:5858`）穿戴。
- 武器槽会严格按当前流派 `WEAPON_RULES` 校验武器类型。

方案（scheme）管理：

- 每个角色可保存多套方案，切换时恢复该方案的心法、弓诀、套装、穿搭、面板选项。
- 方案数据保存在 `game_sim_data_<account>` 中。
- 提供新增、重命名、删除、切换功能。

心法选择：

- `handleOpenXinfaSelector(slotIndex)`（`app.min.js:6087`）打开心法选择弹窗。
- 根据 `ClassConfig.XINFA_RULES` 与 `XINFA_LOCKED` 决定每个槽位可选心法。
- 选择后调用 `normalizeXinfaLoadout` 规范化，并触发 `updateStats`。

面板选项：

- `early-season-bonus-check`：提前获得下半赛季属性（毕业率会虚高）。
- `pvp-mode-check`：首领视为玩家，影响“对玩家单位增效”等属性计算。
- `loan-dingyin-check`：贷款满定音，勾选后弹出具体穿透/增伤数值设置弹窗。

### 3.5 OCR 录入

#### 单件 OCR

- `UIManager.openOcrModal` / `processOcrFile`（`app.min.js:1283`）
- `OCRHandler.recognize`（`app.min.js:324`）调用 Tesseract.js 识别图片文字。
- `OCRHandler.parseText`（`app.min.js:369`）对识别文本做大量清洗、规则映射，输出 `{name, value}` 数组。
- `fillOcrResults`（`app.min.js:1312`）将结果回填到表单主词条、副词条、定音词条。
- 若 Tesseract CDN 加载失败，会自动回退到本地 `js/tesseract/` 目录。

#### 批量 OCR

- `handleBatchOcrConfirm`（`app.min.js:4482`）：解析用户粘贴的 JSON 数组，每项包含 `"识别结果"` 文本。
- `renderBatchOcrResults`（`app.min.js:4509`）：展示 8 个部位的识别结果卡片。
- `saveOcrResultsToAccount`（`app.min.js:4629`）：将识别结果保存到当前角色或新建角色，自动推断武器类型并装备。

### 3.6 导入导出

#### 原生加密导出

- `exportCharacterData`（`app.min.js:5586`）调用 `encryptData`（`app.min.js:5277`）。
- 加密方式：使用 XOR 与 `YYSS2024` 密钥，输出以 `|` 开头、经 `btoa` 编码的字符串。
- `downloadDataAsFile`（`app.min.js:5620`）：将加密字符串下载为 `.txt`。

#### 导入

- `handleFileImport` / `handlePasteImport`（`app.min.js:5632`）读取文本。
- `parseImportData`（`app.min.js:5577`）判断是否是外部装备 V2 格式，否则调用 `decryptData`（`app.min.js:5295`）。
- `confirmImport`（`app.min.js:5669`）确认后**完全覆盖**当前角色装备库。

#### 外部装备 V2 格式

- `decodeExternalEquipmentExportV2`（`app.min.js:5439`）解析以 `YYSLS_EQUIPMENT_EXPORT_V2` 开头的文本。
- `convertExternalEquipmentExportV2`（`app.min.js:5564`）将外部装备结构映射为本站 `Equip` 结构。
- `EXTERNAL_STAT_KEY_MAP`、`EXTERNAL_SLOT_TYPE_MAP`、`EXTERNAL_WEAPON_KEY_MAP`、`EXTERNAL_BUILD_KEY_MAP` 提供大量别名映射，支持英文 key 导入。

#### 本站完整备份/恢复（定制）

`local-customizations.js` 在导出/导入弹窗注入：

- “下载完整备份”：生成一个 `kind: "yysls-tiaolv-full-backup"`、`schemaVersion: 2` 的明文 JSON 文件。
- 单文件包含全部角色、最后选中角色、稳定装备 ID、转律状态、全部流派与方案、方案配置及毕业率手动数据。

- 继续兼容旧版 `1.2` 单角色装备 JSON，旧格式仍按原单角色流程处理。

## 四、计算引擎（核心算法）

### 4.1 计算链路总览

所有毕业率计算最终都走 `YYSLSExcelRuntime.calculate` 或 `YYSLSExcelRuntime.calculatePanel` / `calculateFromPanel`。

JS 侧入口：

- `Calculator.calculateTotal`（`app.min.js:446`）：计算完整面板，返回 `panel` 对象。
- `Calculator.calculateGraduationRate`（`app.min.js:454`）：基于面板计算毕业率、DPS、总伤害。

```
装备 + 心法 + 套装 + 弓诀 + 武库 + 选项
    ↓
Calculator._panelOptions() 构建选项对象
    ↓
buildDiyRaw() → 写入 diyPtr Float64Array
    ↓
wasm.yysls_calc_diy(diyPtr, panelPtr)
    ↓
panelFromArray() → 原始面板
    ↓
applyPurpleBaseAttackPenalty()  紫装惩罚
applyClassPanelRules()          流派特殊规则
applyRateOverflow()             三率溢出
markPanelDamageBonusState()     标记增伤状态
    ↓
返回面板
    ↓
calculateFromPanel() → 毕业率 / DPS / 总伤害 / RDPS
```

### 4.2 WASM 运行时

`excel-runtime.js` 在加载时：

1. `init()` 异步 fetch `assets/wasm/yysls_calc.wasm?v=<ASSET_VERSION>`。
2. 实例化 WebAssembly，获取 exports：`yysls_alloc_f64`、`yysls_diy_input_len`、`yysls_panel_len`、`yysls_class_input_len`、`yysls_calc_diy`、`yysls_calc_class` 等。
3. 分配三个核心指针：`diyPtr`（DIY 输入数组）、`panelPtr`（面板输出数组）、`classPtr`（流派输入数组）。
4. 设置 `runtime.available = true`，并触发 `updateStats()`。

### 4.3 buildDiyRaw：从装备到数组

`buildDiyRaw(options)`（`excel-runtime.js:345`）将前端配置转换为 `Float64Array`：

- `s2`：弓诀名称（精准/会心/会意）
- `t2`：套装名称
- `g9`：武库（通用/本系）
- `f14`：流派名称（治疗流 `牵丝霖` 会被替换为 `牵丝玉`）
- `f4~f7`：4 个心法名称（字符串转 id）
- 8 个槽位分别对应 `k/l/m/n/o/p/q/r` 列：
  - 每列按行写入主词条、副词条、定音词条数值
  - 行号映射：`statInputRow(type)` 定义了每个词条类型对应的行号（如 `劲`=3，`最大外功攻击`=7，`精准率`=8 等）
- 紫装惩罚在 `panelFromArray` 之后单独应用。

### 4.4 面板修正规则

#### 紫装基础攻击惩罚

`applyPurpleBaseAttackPenalty`（`excel-runtime.js:412`）对紫装武器/环/佩扣除基础攻击：

```js
const purpleBaseAttackPenalty = {
  weapon: { "最小外功攻击": 10, "最大外功攻击": 23 },
  ring:   { "最小外功攻击": 13 },
  pendant:{ "最大外功攻击": 20 }
};
```

#### 牵丝流派特殊规则

`applyClassPanelRules`（`excel-runtime.js:427`）：当流派为 `牵丝玉/牵丝翊/牵丝霖` 时，根据最小牵丝攻击是否 ≥ 441 调整牵丝穿透与牵丝伤害加成。

#### 三率溢出

`applyRateOverflow`（`excel-runtime.js:454`）处理：

- 精准率上限 100%，溢出部分按 `seasonResistance`（默认 2.15）折算为“白值溢出”。
- 会心率上限 80%（裂石威 +24%、浣花套装 +5% 提高上限），超出部分折算溢出。
- 会意率上限 40%，超出部分折算溢出。
- 会心+会意+直接会心+直接会意组合上限 100%，超出部分再折算溢出。
- 裂石钧特殊规则：当精准率 > 0 时，会心上限受 `(70 - directCrit * precision / 100) / precision * 100` 限制。

### 4.5 毕业率计算

`YYSLSExcelRuntime.calculateFromPanel` 将面板数据传入 WASM 的 `yysls_calc_class`，得到：

```js
{
  totalDamage,        // 总伤害
  dps,                // 每秒伤害
  rdps,               // 实战 DPS（部分表格支持）
  rdpsGraduationRate, // RDPS 毕业率
  graduationRate      // 毕业率百分比数值
}
```

JS 侧 `getBaseLineByClass`（`app.min.js:4354`）选择基准线：

- 大多数情况用 `ClassConfig.ROTATIONS[class].baseline`。
- 破竹尘在携带特定心法时切换到 `baseline2`。
- 治疗流始终使用 `baseline2`。

毕业率 = 当前输出 / 基准输出 × 100%。

### 4.6 Excel 导出

`excel-export.js`：

1. 根据当前流派找到 `excels/<workbookName>.xlsx` 模板。
2. 使用原生 `DecompressionStream` 解压 xlsx（ZIP）。
3. 解析 `xl/workbook.xml` 与 `xl/_rels/workbook.xml.rels`，定位工作表。
4. 将当前面板相关数值回填到对应单元格。
5. 重新打包并触发下载。

## 五、毕业率分析弹窗（GradModal）

弹窗打开时调用 `GradModal.open()`（`app.min.js:1523`），左侧显示当前毕业率、Excel 对比、版本信息、当前装备列表；右侧为 7 个标签页。

### 5.1 手动填写表格

`renderManualTab`（`app.min.js:1695`）提供一组可手动输入的属性数值，实时调用 `Calculator.calculateGraduationRate` 计算毕业率。用途：

- 与 Excel 表格结果交叉验证。
- 快速调整某项属性观察毕业率变化。

输入缓存 key：`grad_manual_form_v2_<account>_<class>_<flowVersion>`。

本站定制在同一页提供两种输入方式：

- **直接填写面板**：保留原有数值输入和 150ms 防抖计算。
- **按词条数量**：选择“全部按满值”或“全部按承音值”，直接填写各类词条数量，再由 8 件理论金装换算面板并计算毕业率。

用户不需要手动区分首、副词条。系统根据 2.7 节规则自动寻找占用首词条最少的合法分配，显示首词条、 副词条和普通词条计数，并根据当前组合动态禁用不可再增加的词条。若一次输入超出可实现上限，只回退本次修改的词条并提示冲突；不足 40 条的空位视为无输出收益或生存词条。

神力专栏底部利用剩余空间提供弓箭选择，可直接切换精准弓、会心弓或会意弓。选择会同步到当前装备方案，并按新的弓箭立即重新计算毕业率。

数量模式还会在毕业率弹窗右侧实时展示“词条数量最终面板”，其字段分组和数值格式与最佳配装完成后的最终面板一致。精准率、会心率或会意率发生溢出时，会在对应数值后显示“溢出 N% 白值”。增减词条、切换弓箭、满值/承音值或词条组合时都会同步刷新；离开手动页、切回直接填写或关闭弹窗时自动收起。

每个角色、流派和流派版本最多保存 50 个命名词条组合，支持新建、切换、更新、重命名和删除。组合同时保存词条数量及满值/承音值模式，并随完整备份迁移。

直接填写和数量模式使用独立结果节点。原手填防抖任务只能更新手填结果；数量模式在完整面板与毕业率计算结束后一次性写入自己的结果，避免数字先显示临时低值再跳回正确值。

### 5.2 最佳配装（核心算法）

这是调率站最复杂的算法，主函数 `findBestBuild`（`app.min.js:2584`）。

#### 整体流程

```
1. 准备装备数据
   - 按当前流派过滤可用装备
   - 武器按 WEAPON_RULES 匹配
   - 按可用流派限制过滤（可选忽略）

2. 承音化扩展
   - 计算每件装备平均词条占比 getEquipAveragePercent
   - < 92%：只保留承音版
   - 92% ~ 96%：保留原版 + 承音版
   - ≥ 96%：只保留原版

3. 锁定转律目标（可选）
   - 仅保留指定装备的指定副词条
   - 生成该词条所有转律变体

4. 组合穷举
   - 使用 Generator + 栈实现 DFS 深度优先遍历
   - 遍历 8 个槽位的所有组合

5. 快速筛选
   - 维护容量 200 的 Top-K 候选池
   - 每套组合先“贷款满定音”
   - 调用 calculateBuildRate（优先 Excel 运行时）
   - 高级设置过滤不满足面板阈值的组合
   - 最多需要承音过滤（本站定制）

6. Excel 精确复核
   - 对 Top 200 候选再次使用完整计算
   - 排序后保留 Top 20

7. 渲染结果
   - 展示方案编号、毕业率、DPS、弓诀、需承音数量
   - 右侧浮动最终面板
   - 支持切换方案、应用方案
```

#### 关键函数

- `findBestBuild(e, t, n, i, a, o, s, l, w, b)`：
  - `e` 流派，`t` 弓诀，`n` 套装，`i` 心法，`a` 高级设置，`o` 是否指定转律，`s` 是否考虑多弓诀，`l` 是否忽略可用流派，`w` 进度回调，`b` 最多需承音数量。
- `createChengyinVersion`（`app.min.js:2449`）：生成某装备的承音副本，id 加 `_chengyin` 后缀。
- `getEquipAveragePercent`（`app.min.js:2439`）：计算装备平均词条占满值比例。
- `getTransmutationVariants`（`app.min.js:2458`）：生成某装备某副词条的所有转律变体。
- `addFullDingyinToEquips`（`app.min.js:2501`）：给所有装备强制填充满定音数值（武器/环/佩为外功穿透，防具为指定武学技能增伤）。
- `calculateBuildRate`（`app.min.js:2532`）：计算一套装备组合的毕业率，优先使用 Excel 运行时，否则回退。
- `countNeedChengyin`（`app.min.js:1452`）：统计组合中 id 包含 `_chengyin` 的装备数量（即“需承音”数量）。

#### 高级设置

`showAdvancedSettingsModal` / `saveAdvancedSettings`（`app.min.js:2315`）允许设置：

- 最小/最大外功攻击范围
- 最大外功攻击范围
- 精准率范围
- 会心率范围
- 会意率范围

设置保存在 `AppState.allClassLoadouts[class].advancedSettings`。

#### 定制选项

- 考虑不同弓箭套装：勾选后组合数 ×3（同时遍历三种弓诀）。
- 忽略可用流派限制：忽略 `availableClasses` 过滤。
- 最多需要承音：限制 Top 方案中 `(需承音)` 装备数量，在搜索阶段直接过滤。
- 返回 Top 20 而非源站 Top 10。

### 5.3 词条优先级

`renderStatPriorityTab`（`app.min.js:3193`）分析：

- **新增词条收益**：在当前配装基础上，新增一条某种词条（按满值），毕业率提升多少。
- **扣除词条损失**：在当前配装基础上，去掉一条某种词条，毕业率下降多少。

排除已装备武器专属的同类型武学增效，避免重复计算。

实现上对每个候选词条调用 `calcRateWithStatModifier`（`app.min.js:3413`）做 `add`/`remove` 操作，然后 `Calculator.calculateGraduationRate`。

### 5.4 培养建议

分两层：

#### 总结层

`renderCultivationTab`（`app.min.js:3609`）即时展示：

- 当前所有词条按满值比统计（主+副，不含定音）。
- 当前定音词条总体占满值百分比。
- 每个定音词条升级至满值可带来的毕业率提升。

#### 全局最优配置

`calculateOptimalStats`（`app.min.js:3443`）计算在当前流派、心法、套装、武库下，理论上最优的 40 条面板词条分布：

- 分别对三种弓诀做贪心搜索。
- 每轮在 8 个部位中选择能带来最大毕业率提升的一条词条加入。
- 共 40 轮，得到每种弓诀下的最优词条分布。
- 取三种弓诀中最终毕业率最高者。

优先使用 `generated-best40-stats.js` 中的预计算结果；无预计算或赛季数据更新时，执行完整计算并缓存到 `best40StatsCache`。

这里的“最优 40 词条”是培养建议的独立预计算/贪心模型，不应与 5.1 节可由用户保存的“按词条数量”组合混为一谈。2.7 节的特殊词条硬上限当前作用于手动数量组合；最佳 40 仍按其既有生成数据与算法运行。

#### 单部位最优

`calculateCultivationAnalysis`（`app.min.js:3852`）与 `findBestStatsForSlotAsync`（`app.min.js:3278`）对每个部位遍历：

- 所有可能的主词条。
- 所有可能的 4 条副词条组合。
- 找到使整体毕业率最高的主副词条配置，并给出提升空间。

### 5.5 转律建议

只有110级非承音装备可以进入转律建议。装备选择器会过滤其他等级和承音装备，计算入口与转律变体生成器还会再次校验；其他等级装备仍可作为普通装备参与最佳配装。

`renderTransmutationTab`（`app.min.js:2078`）流程：

1. 选择左侧某部位装备（或当前穿搭装备）。
2. 选择该装备的一条副词条。
3. 点击“开始计算”后，内部调用 `findBestBuild` 并锁定该装备该副词条，生成所有转律变体参与穷举。
4. 找出最高毕业率方案，与当前穿搭对比，给出差值。
5. 渲染建议：是否转律、该副词条最佳转律目标、最佳方案装备清单。

### 5.6 单件装备对比

`renderComparison`（`app.min.js:2013`）流程：

1. 从数据库筛选同部位装备（武器需同类型）。
2. 用每件候选装备替换当前部位的装备。
3. 可选勾选“假设满承音”或“冻结当前定音”。
4. 计算替换后的毕业率与当前毕业率差值。
5. 按毕业率排序展示。

## 六、本站定制功能（local-customizations.js）

### 6.1 装备等级与标签

- 在装备录入弹窗注入 `level-select`（新建装备默认 110，可选 110/105/100/96）。
- 在装备卡片、面板槽位、最佳配装结果中显示 `[110]`/`[105]`/`[100]` 等级标签，颜色分别为金/蓝/灰。
- `getDB` 默认旧数据 `level = 105`。

### 6.2 完整备份与恢复

- `downloadJsonDataAsFile`：导出全部角色及可迁移的持久化数据，保留装备 ID 和跨数据引用。
- `handleJsonFileImport`：识别完整备份或旧版 `1.2` JSON；完整备份先校验、预览、确认，再原子写入。
- 完整备份不包含最佳 40、搜索结果等可重建缓存，也不包含网站主题等调率工具之外的数据。

### 6.3 手动毕业率词条数量模式

- `getManualStatCountLimit` 同时执行普通词条总数和特殊词条部位上限。
- 快捷专栏按当前流派筛选武器增效；无关流派的武器增效不会显示或参与计算。
- `__statCountConfig` 保存输入模式、满值/承音值选择、当前数量和命名组合。
- 两种输入模式的毕业率结果节点相互隔离，防止旧防抖任务覆盖数量模式结果。

### 6.4 转律状态管理

仅对110级非承音装备在编辑弹窗注入“转律状态”区域，游戏状态只有两种：

- 未转律：尚未指定转律副词条；网站不必写入记录，缺失记录即表示未转律。
- 已转律：必须从装备当前实际存在的副词条中指定一个，记录为 `{state:"active", subStatIndex, modelVersion:2}`。首词条和其他副词条不能被指定。

状态保存在 `zhuanlv_status_<account>`，key 为装备 id。未转律装备显示灰色标签；已转律装备显示指定副词条的序号、名称和箭头，不再保存或展示1~3个可转目标。

非110级、承音、缺失装备、无效副词条引用及旧模型记录不会被恢复。升级到两状态模型时，全部旧 active 状态按照既定迁移策略重置为未转律；完整备份版本仍为2，只接受带 `modelVersion:2` 的合法 active 记录。

本阶段暂时隐藏“转律建议”和最佳配装“指定转律目标”入口，普通最佳配装不使用转律缓存。底层转律池和变体生成器保留，待后续讨论自由切换、方案保存和收益计算后再启用。

### 6.5 取消搜索按钮

- 监听 `#best-build-progress-text` 出现，自动在进度条下方插入“取消搜索”按钮。
- 点击设置 `GradModal.state.bestBuildCancelled = true`，中断 `findBestBuild` 的 Generator 循环。

### 6.6 最佳配装词条汇总

## 七、数据安全与备份

### 7.1 数据存储

- 所有数据存储在浏览器 `localStorage`。
- 清除浏览器缓存或更换浏览器/设备会导致数据丢失。
- 无云端同步机制。

### 7.2 备份建议

强烈建议定期导出：

- 点击“导出/导入数据” → “下载完整备份”。
- 将 `.txt` 或 `.json` 文件保存到云盘或安全位置。
- 在清理浏览器数据前、录入大量装备后、完成满意方案后都应备份。

完整 JSON 是跨设备迁移的首选；原生加密 `.txt` 和旧版单角色 JSON 主要用于兼容原有装备导入流程。

### 7.3 跨设备迁移

1. 原设备点击“下载完整备份”，得到带日期时间的 JSON 文件。
2. 将文件发送到新设备。
3. 新设备打开调率站，点击“恢复完整备份”并查看角色、装备、方案和同名角色预览。
4. 确认同名角色覆盖后恢复，页面刷新并自动选中备份记录的最后角色。

**注意**：同名角色按角色完整替换；备份中未出现的本地角色不会删除。取消确认、文件损坏、版本不支持或结构校验失败时不会写入任何数据。

## 八、常见问题与调试

### 8.1 为什么网页毕业率与 Excel 不一致？

可能原因：

- 心法、弓诀、套装配置不一致。
- “提前获得下半赛季属性”或“首领视为玩家”选项与 Excel 设置不同。
- 装备数值录入错误（如 OCR 将“敏”识别为“劲”）。
- 某些心法在 Excel 表格中尚未正确计算，会弹出“心法计算提示”。
- 流派版本（flow version）选择不同。

排查方法：使用“手动填写表格”标签页逐项对比。

### 8.2 最佳配装结果里出现我没见过的装备？

最佳配装只遍历数据库中**已有**装备。如果显示 `(需承音)`，表示这是系统基于你已有装备生成的承音版本，需要后续培养；`(承音)` 表示数据库中本身就是承音装备。

### 8.3 为什么最佳配装找不到方案？

常见原因：

- 数据库装备不足或没有某部位装备。
- 高级设置过滤条件太严格，没有组合满足。
- 当前流派没有对应武器类型的装备。
- 装备数量过多导致组合爆炸但超时/取消。

### 8.4 OCR 识别不准确怎么办？

- 确保截图背景干净、文字清晰。
- 不要截到词条左侧竖线或其他 UI 元素。
- 识别后务必人工核对所有数值。
- 单件 OCR 需要 Tesseract 加载，首次可能较慢。

### 8.5 为什么最高只能到 99.9% 毕业率？

说明：100% 毕业率的面板在最大外功攻击上比模拟面板多 1，因此通常最高只能模拟到 99.9%。如果超过 100%，则可能是所选套装/心法非基准配装，或表格基准线有误。

### 8.6 面板数值看起来不对？

请检查：

- 天赋、蹊跷、左四件叠音、武库是否已培养满（工具按全满作为基础面板）。
- 紫装是否在录入时勾选【紫装】，否则不会应用紫装基础攻击惩罚。
- 是否有装备词条或数值录入错误。
- 当前流派版本是否正确。

### 8.7 为什么按词条数量不能无限增加某些神力词条？

40 条只是一套装备的普通词条总量，不代表任意词条都能出现 40 次。对首领单位增伤只能来自胫甲和腕甲，全武学增效只能来自环和佩，因此各自最多 2 条；每种具体武器武学增效绑定一件对应武器，因此最多 1 条。双武器流派可以各选一种不同武器增效。

这些限制用于排除游戏内无法实现的理论组合，避免毕业率虚高。达到上限后加号会禁用；直接输入或载入旧组合中的超额数量也会自动收敛到合法值。

## 十一、游戏装备机制

> 本章只说明游戏机制和配装逻辑，不讨论程序、文件或计算实现。

### 11.1 一套配装的组成

一套完整配装共有 8 件装备：

- 2 件武器；
- 1 件环；
- 1 件佩；
- 1 件冠胄；
- 1 件胸甲；
- 1 件胫甲；
- 1 件腕甲。

每件装备按 1 条主词条和 4 条副词条计算，因此一套完整装备共有 40 条普通词条。定音是额外属性，不计入这 40 条普通词条。

### 11.2 词条的主要类别

配装时常见的输出词条可分为：

- **三率**：精准率、会心率、会意率；
- **五维**：劲、敏、势等基础属性；
- **攻击**：最小/最大外功攻击，以及鸣金、裂石、牵丝、破竹等流派攻击；
- **穿透**：外功穿透及各流派穿透；
- **神力**：全武学增效、具体武器武学增效、对首领单位增伤、对玩家单位增效等；
- **指定武学增伤**：针对某个流派核心武学或技能类型生效。

词条价值不能只看单条数值。三率是否接近上限、流派技能中不同伤害类型的占比、当前心法与套装加成，都会改变一条词条带来的实际收益。

### 11.3 首词条、副词条与部位上限

一套装备有 8 个首词条位和 32 个副词条位。“最多 40 条”只是总容量，实际组合还要满足每个部位 1 个首词条、4 个副词条。同一种属性在同一件装备上最多出现一次副词条，但可以同时成为该装备的首词条。

| 词条 | 来源部位 | 整套最多 |
|------|----------|----------|
| 对首领单位增伤 | 胫甲、腕甲 | 2 条 |
| 对玩家单位增效 | 胫甲、腕甲 | 2 条 |
| 全武学增效 | 环、佩 | 2 条 |
| 单体类奇术增伤 | 冠胄、胸甲 | 2 条 |
| 群体类奇术增伤 | 冠胄、胸甲 | 2 条 |
| 某一种具体武器武学增效 | 对应类型武器 | 1 条 |

例如，拳甲武学增效绑定拳甲，因此整套最多 1 条；双武器流派可以各有一种不同的武器增效，但同一种武器增效不能重复堆叠。

大小外攻的首词条位由两件武器、环、佩共享；三率的首词条位由四件防具共享；劲会使用武器、胫甲、腕甲；敏、势和无相攻击只能使用武器首词条。因而一种属性超过 8 条副词条以后，额外数量会开始占用它有资格使用的首词条，并压缩其他属性的空间。

例如大外 12 条恰好是 8 副 + 4 首，不能再增加；大外 10 + 小外 10 各需 2 个首词条，可以实现；大外达到 11 后已经占用 3 个共享首位，小外便最多 9 条。精准 10 + 会心 10 后同样已经占用四个防具首位，会意最多只能保留 8 条。

### 11.4 流派、武器与武学增效

不同流派使用固定的双武器组合：

| 流派 | 武器组合 | 主要相关武器增效 |
|------|----------|------------------|
| 鸣金虹、鸣金影 | 剑 + 枪 | 剑武学增效 |
| 破竹尘 | 伞 + 绳标 | 伞武学增效 |
| 破竹风 | 双刀 + 绳标 | 双刀、绳标武学增效 |
| 破竹鸢 | 拳甲 + 绳标 | 拳甲武学增效 |
| 裂石威 | 陌刀 + 枪 | 陌刀武学增效 |
| 裂石钧 | 横刀 + 陌刀 | 陌刀武学增效 |
| 裂石钧（纯唐） | 横刀 + 陌刀 | 横刀武学增效 |
| 牵丝玉 | 伞 + 扇 | 伞武学增效 |
| 牵丝翊 | 鼓 + 扇 | 鼓、扇武学增效 |
| 牵丝霖 | 伞 + 扇 | 扇武学增效 |

“装备了某种武器”不代表该武器增效一定对当前流派同样有效。应根据该流派实际造成伤害或治疗的武学来源选择对应增效，避免把无关武器增效当成有效收益。

### 11.5 满值、承音与词条品质

- **满值**：把一条词条按其理论最高数值计算。
- **承音值**：通常接近满值，当前采用约 94% 满值作为统一比较标准。
- **普通装备实际值**：可能高于或低于承音比较值，应以装备上显示的真实数值为准。

比较词条组合时，可以统一按满值观察理论上限，也可以统一按承音值观察更接近培养目标的结果。两种标准只能用于横向比较，不能混在同一组方案中随意切换，否则比较基础会不一致。

### 11.6 金装、紫装与基础攻击

金装和紫装不能只按词条数量直接等同。紫装在武器、环和佩等部位存在基础攻击差距：

| 部位 | 紫装基础攻击差距 |
|------|------------------|
| 武器 | 最小外功攻击少 10，最大外功攻击少 23 |
| 环 | 最小外功攻击少 13 |
| 佩 | 最大外功攻击少 20 |

因此，即使紫装词条类型看起来很好，也要把基础攻击差距一起纳入配装比较。

### 11.7 定音与转律

定音是独立于 40 条普通词条之外的额外属性。常见方向为：

- 武器、环、佩偏向外功穿透；
- 防具偏向指定武学技能增伤。

比较装备时需要区分当前真实定音和假设定音达到满值的情况。后者适合比较装备本体与词条结构的理论上限，但不代表当前角色已经拥有这些定音数值。

转律用于改变装备的可转词条方向。转律后的词条仍受装备部位、流派武库和可选词条池限制；不能把任意词条转到任意装备上。

### 11.8 套装、弓诀、心法与武库

一套配装的实战收益并不只由装备词条决定：

- **套装**提供固定属性或战斗加成，会改变某些词条的边际收益；
- **弓诀**分别偏向精准、会心或会意，应结合当前三率缺口选择；
- **心法**会改变技能伤害结构、直接会心/会意或特定武学收益；
- **武库**决定流派属性方向，也会影响可用的转律词条；
- **赛季加成和PVP战斗环境**会改变属性的实际收益。

因此，同一套 40 条词条在不同心法、套装、弓诀或赛季条件下，实战表现可能不同。比较多套方案时，必须保持这些外部条件一致。

### 11.9 三率上限与溢出

- 精准率通常按 100% 为上限；
- 会心率通常按 80% 为基础上限，部分流派或套装可以提高；
- 会意率通常按 40% 为上限；
- 会心、会意以及直接会心/直接会意共同受到组合上限约束。

超过有效上限后，新增三率的收益会明显下降或转化为溢出收益。因此，不能只看“某条三率的单条收益很高”就无限堆叠；越接近上限，越需要重新比较攻击、神力或其他词条。

三率面板百分比通常称为“黄值”，溢出提示使用“白值”。当前赛季抗性换算系数为 2.15：

```
溢出白值 = 超出上限的黄值 × 2.15
超出上限的黄值 = 溢出白值 ÷ 2.15
```

例如显示“溢出 9.1% 白值”，对应约 `9.1 ÷ 2.15 = 4.23%` 黄值超出有效上限。若这是精准率且上限为 100%，原始精准率约为 104.23%，最终有效精准率显示为 100%，另外标记溢出的 9.1% 白值。

会心率还会受到流派、套装、直接会心和会心/会意组合上限影响，因此它的溢出不一定只等于“面板会心率减 80%”；应以完整战斗条件下得到的白值溢出为准。

### 11.10 配装比较原则

合理比较多套配装应遵守：

1. 使用同一流派及同一流派版本；
2. 使用相同心法、套装、弓诀、武库和赛季条件；
3. 统一采用真实值、承音值或满值中的一种比较标准；
4. 保证词条组合满足 40 条总量和装备部位上限；
5. 区分当前真实定音与假设定音达到满值；
6. 注意三率上限和溢出，避免只比较表面词条数量。

装备、词条、心法与套装之间存在联动，不能脱离完整配装条件，只凭单件装备或单条属性判断最终强弱。
