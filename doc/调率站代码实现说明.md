# 调率站代码实现说明

> 面向开发者和维护者。产品规则与结果口径见[《调率站产品与计算逻辑》](调率站产品与计算逻辑.md)。

## 一、实现总览

调率站是一个浏览器端静态应用。计算在本地完成，云端只负责可选的账号与备份同步。

```text
index.html
  ↓
生成字符串与元数据
  ↓
Excel 兼容运行时 + Rust/WASM
  ↓
本地定制层 + 主业务层
  ↓
云备份与 Excel 导出
```

主要文件职责：

| 文件 | 职责 |
| --- | --- |
| `index.html` | 页面结构、弹窗容器、脚本加载顺序与缓存版本 |
| `assets/js/app.min.js` | 主状态、装备管理、页面交互、毕业率分析和搜索流程 |
| `assets/js/excel-runtime.js` | 面板输入适配、WASM 调用、流派输入映射和结果归一化 |
| `assets/wasm/yysls_calc.wasm` | 面板与流派伤害计算核心 |
| `assets/js/generated-calc-metadata.js` | 流派字段、默认值、基准、最大值和承音值 |
| `assets/js/generated-calc-strings.js` | WASM 使用的字符串 ID 表 |
| `assets/js/generated-best40-stats.js` | 培养建议使用的预计算数据 |
| `assets/js/local-customizations.js` | 本站定制、迁移、完整备份、手动数量模式和结果增强 |
| `assets/js/best-build-algorithms.js` | 最佳配装算法注册与分派 |
| `assets/js/cloud-backup.js` | Supabase 登录、自动备份、冲突保护和历史快照 |
| `assets/js/excel-export.js` | 把当前数据写回对应 Excel 模板并下载 |
| `assets/js/tesseract.min.js` | OCR 识别依赖 |

## 二、加载与全局接口

`index.html` 的业务脚本顺序是运行时契约：

1. `generated-calc-strings.js`
2. `generated-calc-metadata.js`
3. `generated-best40-stats.js`
4. `excel-runtime.js`
5. `local-customizations.js`
6. `best-build-algorithms.js`
7. `app.min.js`
8. Supabase UMD SDK
9. `cloud-backup.js`
10. `excel-export.js`

关键全局对象：

| 对象 | 用途 |
| --- | --- |
| `CommonData` | 槽位、词条池、上限、套装、武器和转律池 |
| `ClassConfig` | 流派、武器规则、心法规则和旧版输出配置 |
| `AppState` | 当前角色、穿搭、方案、心法、武库、版本与开关 |
| `UIManager` | 页面元素、事件和主界面渲染 |
| `GradModal` | 毕业率分析各标签页与最佳配装流程 |
| `YYSLSExcelRuntime` | 主计算接口 |
| `YYSLSBestBuildAlgorithms` | 搜索算法注册中心 |
| `TiaolvLocalCustomizations` | 完整备份及本地定制公共能力 |

不要随意调整加载顺序。元数据必须先于运行时，算法注册中心必须先于主脚本注册默认算法，Supabase SDK 必须先于云备份初始化。

## 三、运行状态与数据模型

`AppState` 维护当前会话状态：

- 当前角色及八个已装备槽位；
- 全流派配装和多方案；
- 当前心法、套装、弓诀和武库；
- 赛季、PVP、贷款定音和流派额外输入；
- 当前方案的转律覆盖层；
- 最佳配装缓存与展示状态。

装备对象至少包含稳定 ID、部位、品质、等级、武器类型、主词条、副词条、定音、承音及流派限制。计算前必须先规范化旧数据，避免历史字段缺失改变候选合法性。

主要本地存储按角色隔离：

| Key 模式 | 内容 |
| --- | --- |
| `game_account_list` | 角色列表 |
| `game_equip_data_<account>` | 装备仓库 |
| `game_sim_data_<account>` | 配装、方案和计算选项 |
| `zhuanlv_status_<account>` | 转律状态 |
| `grad_manual_form_v2_<account>_<class>_<flow>` | 手动毕业率配置 |
| `last_selected_account` | 最近角色 |

角色重命名和完整恢复必须同步迁移所有角色级 key。装备稳定 ID 不得因导入、恢复或方案切换而变化。

## 四、主计算数据流

所有常规毕业率入口最终应优先走 `YYSLSExcelRuntime`：

```text
页面/分析功能
  ↓
统一 options
  ↓
calculate()
  ├─ calculatePanel()
  └─ collectBonuses()
       ↓
calculateFromPanel()
       ↓
总伤害、DPS、毕业率、RDPS
```

### 4.1 统一输入

调用方需要提供：

- `equippedItems`
- `className`、`flowName`、`flowVersion`
- `bow`、`xinfa`、`setName`、`armory`
- 赛季与 PVP 开关
- 贷款定音及数值
- `classInputOverrides`
- 临时属性修正和方案覆盖后的装备

主页、手动面板、词条收益、培养建议、转律建议、单件比较和最佳配装必须复用同一输入口径。

### 4.2 装备到面板

`calculatePanel()` 先由 `buildDiyRaw()` 把基础配置、八件装备、四个心法、弓诀、套装、武库和词条值编码为连续数值数组，再调用：

```text
yysls_calc_diy(diyPtr, panelPtr)
```

输出经 `panelFromArray()` 还原为面板对象，然后按顺序执行：

1. 紫装基础攻击惩罚；
2. 流派面板规则；
3. 精准、会心、会意溢出；
4. 增伤状态标记。

`collectBonuses()` 另外汇总不适合直接进入 DIY 单元格的定音、穿透、武器增效、奇术增伤和临时修正。`calculateFromPanel()` 再把这些显式 bonus 合入面板，必须通过 damage-state 标记防止重复除以赛季抗性。

### 4.3 面板到流派输入

`calculateFromPanel()` 先通过 `resolveFlowName()` 和 `flowIds` 确定流派 ID，再用 `buildClassRaw()` 将通用面板映射为该流派的输入数组。

映射来源包括：

- `classFields`、`classFieldKinds` 和 `classDefaultValues`
- `classValueFields`
- `classXinfaInputs`
- `classSetFields`
- `classSkillDingyinFields`
- `classElements`

字符串输入先转换为 `generated-calc-strings.js` 中的数值 ID。百分比在写入流派数组时统一转换为小数，增伤字段根据 damage-state 决定是否需要抗性换算。

破竹鸢示例映射：基础外功进入 `b5/c5`，破竹攻击进入 `b13/c13`，三率进入 `c16/c17/c18`，拳甲和绳标增效进入 `c22/c23`，全武、奇术、首领及定音进入对应流派字段。

### 4.4 流派计算与毕业率

流派输入写入 `classPtr` 后优先调用：

```text
yysls_calc_class_outputs(flowId, classPtr, classOutputPtr)
```

输出顺序为：

1. `totalDamage`
2. `dps`
3. `graduationRatio`
4. `rdps`
5. `rdpsGraduationRatio`

如果当前 WASM 只提供 `yysls_calc_class`，运行时用总伤害除以 `classRotationStats.useTime` 得到 DPS。

毕业率优先使用 WASM 返回的 `graduationRatio × 100`；没有直接结果时，回退为：

```text
dps ÷ baselineDps × 100
```

基准优先取 `generated-calc-metadata.js` 的 `classRotationStats`，再回退旧 `ClassConfig.ROTATIONS`。返回对象统一包含 `panel`、`totalDamage`、`dps`、`rdps`、`useTime`、`baselineTotal`、`graduationRate` 和元数据。

## 五、双计算路径与一致性

主业务仍保留旧 `Calculator.calculateTotal()` 和旧输出轴逻辑作为兼容回退。当前权威路径应是：

```text
generated-calc-metadata.js
+ excel-runtime.js
+ yysls_calc.wasm
```

风险点：

- WASM 未就绪时，页面可能暂时显示旧路径结果；
- 元数据、WASM 和 Excel 模板版本不一致会导致结果漂移；
- 新规则只修改主路径而未同步旧回退时，同一输入可能产生两种结果；
- 增伤被重复换算或遗漏 damage-state 会造成面板一致但 DPS 不一致；
- `flowName`、`flowVersion` 或心法映射错误会把面板送入错误输出轴。

维护原则：新增计算规则优先更新生成源与 WASM，并为主路径建立固定样本；旧路径只承担容错，不作为数值权威。

## 六、最佳配装实现

`YYSLSBestBuildAlgorithms` 提供 `register/get/list`，主脚本注册 `legacy-exhaustive` 默认算法。搜索分为：

1. 按部位构造候选装备；
2. 应用流派、武器、实体装备互斥、词条数量和面板阈值；
3. 根据模式生成不转律、已转律或待转律候选；
4. 将装备预编译为 `rawEntries`、`bonusEntries` 和紫装惩罚；
5. 复用基础输入，批量调用 `calculateBestBuildCompiled()`；
6. 以毕业率维护候选堆并生成 Top20；
7. 对候选执行最终复核、去重和展示。

最佳配装的关键不变量：

- `getOriginalEquipId` 保证转律副本仍按同一实体装备互斥；
- 缓存摘要必须包含流派环境、弓诀、限制与转律模式；
- Top20 按“八件原始装备 ID + 承音状态”去重，同一基础配装只保留最高毕业率转律组合；
- `transmutationSelections` 是方案覆盖层，计算时生成临时装备，不修改装备库原对象；
- 取消搜索需要终止后续批次和结果写入。

转律完整规则见[《转律机制说明》](转律机制说明.md)。

## 七、分析功能复用

- **手动面板**：直接构造面板或先把词条数量分配到八件理论装备，再调用统一计算链。
- **词条优先级**：对当前配置添加或移除目标词条，比较毕业率差值。
- **培养建议**：逐部位模拟词条和定音改善，汇总边际收益。
- **转律建议**：替换指定副词条，遍历合法目标，比较完整配装毕业率。
- **单件比较**：只替换一个槽位，保持其余环境不变后重算。

这些入口不得自行复制一套简化毕业率公式，否则会与主页和最佳配装产生口径分叉。

## 八、OCR、导入导出与备份

### 8.1 OCR

`OCRHandler` 使用 Tesseract 识别单件或批量截图，解析部位、名称、主副词条和数值。识别结果必须经过用户确认与装备规范化后才写入仓库；OCR 失败不应影响现有装备数据。

### 8.2 导入导出

- 角色数据导出用于单角色迁移；
- 外部装备 V2 格式用于跨工具导入；
- 完整 JSON 备份由 `TiaolvLocalCustomizations` 生成，包含全部角色、稳定装备 ID、配装方案、转律状态和手动毕业率数据；
- `excel-export.js` 读取对应模板，把当前计算输入回填到工作簿并下载。

完整恢复先校验格式和版本，再暂存旧值、写入新值并触发状态刷新；任何一步失败都应回滚，避免半恢复状态。

### 8.3 云备份

`cloud-backup.js` 使用 Supabase 保存完整状态，策略是本地优先：

- 本地变化写入 dirty 标记；
- 上传前比较上次基线哈希与当前云端哈希；
- 发现其他设备更新时暂停自动上传并要求用户选择；
- 恢复、上传和历史快照使用独立状态；
- 云端失败不能阻止本地使用和手动备份。

## 九、数据安全原则

- 本地装备库是主要数据源，计算、OCR 或搜索失败不得破坏已保存装备；
- 完整恢复采用“先校验、再暂存、后写入、失败回滚”，禁止半量覆盖；
- 云备份上传前比较本地基线与云端哈希，发现多设备分叉时暂停自动覆盖；
- 可重建缓存不进入权威备份，稳定装备 ID、方案和转律状态必须进入；
- 导入旧数据先规范化并报告跳过项，不能因单件异常放弃全部有效数据；
- 方案转律只使用临时覆盖层，任何分析和预览都不得修改装备库原对象。

## 十、本地定制与上游同步

本地定制同时分布在 `local-customizations.js`、`app.min.js`、`index.html`、计算运行时和生成数据中。同步上游时：

1. 以最新上游 `app.min.js` 为基线重新应用定制，不在旧文件上增量覆盖；
2. 保留 `local-customizations.js` 及其加载标签；
3. 检查装备等级、完整备份、手动数量模式、承音、转律、Top20、取消搜索和统计摘要；
4. 运行 `check_tiaolv_customizations.sh` 验证跨文件链路。

完整定制清单以[《调率站本地定制清单》](tiaolv-local-customizations.md)为准。

## 十一、排错与验证

### 11.1 面板不一致

依次确认：装备是否应用方案覆盖、承音/真实值口径、贷款定音、紫装惩罚、心法套装武库、赛季/PVP、三率溢出及增伤状态。

### 11.2 DPS 或毕业率不一致

依次确认：流派名称和版本、WASM 是否就绪、`classRotationStats` 基准、心法字符串映射、百分比单位、输出轴时长，以及是否走了旧回退路径。

### 11.3 最佳配装不一致

依次确认：候选部位、实体装备互斥、流派限制、弓诀集合、承音上限、转律模式、缓存摘要、Top20 去重键和最终复核。

### 11.4 固定回归样本

每个流派至少保留一套固定配置，验证：

- 最终面板关键字段；
- 总伤害、DPS 和毕业率；
- 新增/移除一条词条的差值；
- 真实值、承音值与贷款定音；
- 转律覆盖前后；
- 最佳配装快速结果与最终复核。

## 十二、维护与发布

- 不直接手改 `generated-*.js`；应修改生成源并重新生成，保证元数据与 WASM 同版本。
- 修改调率站前端文件时，更新 `index.html` 中对应脚本的 `?v=`，格式为 `YYYYMMDDHHmm`。
- 代码或数据变更后运行 `./skills/tiaolv-sync/scripts/check_tiaolv_customizations.sh`。
- 发布前运行 Hugo 构建，再通过 `publish_site.sh` 只提交本次任务相关路径。
- 文档中的产品规则、技术实现、转律机制和定制清单分别维护，避免同一事实多处漂移。
