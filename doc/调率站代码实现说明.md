# 调率站代码实现说明

> 面向开发者和维护者。产品规则与结果口径见[《调率站产品与计算逻辑》](调率站产品与计算逻辑.md)。

## 一、实现总览

调率站是一个浏览器端静态应用。计算在本地完成，云端只负责可选的账号与备份同步。

```text
index.html
  ↓
生成字符串与元数据
  ↓
Excel 兼容运行时
  ├─ 面板 Rust/WASM
  └─ Excel Rust/WASM
  ↓
本地定制层 + 主业务层
  ↓
云备份与 Excel 导出
```

主要文件职责：

| 文件 | 职责 |
| --- | --- |
| `index.html` | 页面结构、弹窗容器、脚本加载顺序与缓存版本 |
| `assets/js/app.min.js` | 主状态、装备管理、页面交互、毕业率分析和搜索流程 |
| `assets/js/excel-runtime.js` | 面板输入适配、WASM 调用、流派输入映射和结果归一化 |
| `assets/wasm/yysls_panel.wasm` | 第一步：装备与配置生成最终面板 |
| `assets/wasm/excel/*.wasm` | 第二步：11个表格版本各自直接编译，最终面板进入当前流派 Excel 公式，计算伤害与毕业率 |
| `assets/js/generated-calc-metadata.js` | 流派字段、默认值、基准、最大值和承音值 |
| `assets/js/generated-calc-strings.js` | WASM 使用的字符串 ID 表 |
| `assets/js/generated-best40-stats.js` | 培养建议使用的预计算数据 |
| `assets/js/local-customizations.js` | 本站定制、迁移、完整备份、手动数量模式和结果增强 |
| `assets/js/best-build-algorithms.js` | 最佳配装算法注册与分派 |
| `assets/js/cloud-backup.js` | Supabase 登录、自动备份、冲突保护和历史快照 |
| `assets/js/excel-export.js` | 把当前数据写回对应 Excel 模板并下载 |
| `assets/js/tesseract.min.js` | OCR 识别依赖 |

## 二、加载与全局接口

`index.html` 的业务脚本顺序是运行时契约：

1. `generated-calc-strings.js`
2. `generated-calc-metadata.js`
3. `generated-best40-stats.js`
4. `excel-runtime.js`
5. `local-customizations.js`
6. `best-build-algorithms.js`
7. `app.min.js`
8. Supabase UMD SDK
9. `cloud-backup.js`
10. `excel-export.js`

关键全局对象：

| 对象 | 用途 |
| --- | --- |
| `CommonData` | 槽位、词条池、上限、套装、武器和转律池 |
| `ClassConfig` | 流派、武器规则、心法规则和旧版输出配置 |
| `AppState` | 当前角色、穿搭、方案、心法、武库、版本与开关 |
| `UIManager` | 页面元素、事件和主界面渲染 |
| `GradModal` | 毕业率分析各标签页与最佳配装流程 |
| `YYSLSExcelRuntime` | 主计算接口 |
| `YYSLSBestBuildAlgorithms` | 搜索算法注册中心 |
| `TiaolvLocalCustomizations` | 完整备份及本地定制公共能力 |

不要随意调整加载顺序。元数据必须先于运行时，算法注册中心必须先于主脚本注册默认算法，Supabase SDK 必须先于云备份初始化。

## 三、运行状态与数据模型

`AppState` 维护当前会话状态：

- 当前角色及八个已装备槽位；
- 全流派配装和多方案；
- 当前心法、套装、弓诀和武库；
- 赛季、PVP、贷款定音和流派额外输入；
- 当前方案的转律覆盖层；
- 最佳配装缓存与展示状态。

装备对象至少包含稳定 ID、部位、品质、等级、武器类型、主词条、副词条、定音、承音及流派限制。计算前必须先规范化旧数据，避免历史字段缺失改变候选合法性。

主要本地存储按角色隔离：

| Key 模式 | 内容 |
| --- | --- |
| `game_account_list` | 角色列表 |
| `game_equip_data_<account>` | 装备仓库 |
| `game_sim_data_<account>` | 配装、方案和计算选项 |
| `zhuanlv_status_<account>` | 转律状态 |
| `grad_manual_form_v2_<account>_<class>_<flow>` | 手动毕业率配置 |
| `last_selected_account` | 最近角色 |

角色重命名和完整恢复必须同步迁移所有角色级 key。装备稳定 ID 不得因导入、恢复或方案切换而变化。

## 四、主计算数据流

所有常规毕业率入口最终应优先走 `YYSLSExcelRuntime`：

```text
页面/分析功能
  ↓
统一 options
  ↓
calculate()
  ├─ calculatePanel()
  └─ collectBonuses()
       ↓
calculateFromPanel()
       ↓
总伤害、DPS、毕业率、RDPS
```

### 4.1 统一输入

调用方需要提供：

- `equippedItems`
- `className`、`flowName`、`flowVersion`
- `bow`、`xinfa`、`setName`、`armory`
- 赛季与 PVP 开关
- 贷款定音及数值
- `classInputOverrides`
- 临时属性修正和方案覆盖后的装备

主页、手动面板、词条收益、培养建议、转律建议、单件比较和最佳配装必须复用同一输入口径。

### 4.2 装备到面板

`calculatePanel()` 先由 `buildDiyRaw()` 把基础配置、八件装备、四个心法、弓诀、套装、武库和词条值编码为连续数值数组，再调用：

```text
yysls_panel.wasm
  ↓
yysls_calc_diy(diyPtr, panelPtr)
```

`yysls_panel.wasm` 拥有独立线性内存，只导出 `yysls_calc_diy`、DIY 输入长度和面板输出长度等第一步接口，不包含流派伤害与毕业率接口。

输出经 `panelFromArray()` 还原为面板对象，然后执行精准、会心、会意溢出和增伤状态标记。金装/紫装的固定攻击差值已经在 Panel WASM 内计算，JavaScript 不再事后扣减。

Panel WASM 就绪并恢复最近角色后，主页会立即预加载当前 `flowName` 对应的 Excel 专用 WASM；模块加载期间毕业率显示“计算中…”，加载完成后由运行时自动触发 `updateStats()`。切换流派或表格版本时同样只加载新选择的一个模块，已经加载的模块继续复用，不会在首屏下载其余流派。

`collectBonuses()` 另外汇总不适合直接进入 DIY 单元格的定音、穿透、武器增效、奇术增伤和临时修正。`calculateFromPanel()` 再把这些显式 bonus 合入面板，必须通过 damage-state 标记防止重复除以赛季抗性。

#### 4.2.1 当前基础面板与叠加关系

新版 `yysls_panel.wasm` 使用本地 `yysls-assistant.cn` 快照的 `110_RBDZ_DOWN` 数据。它不再使用旧版“十套流派基础面板”，而是从同一套公共裸角色数据出发，按所选流派实时加入武学和天赋：

```text
公共裸角色属性
+ 所选流派的武学与天赋
+ 四本心法
+ 八槽位装备固定属性与调音词条
+ 套装、弓诀、武库
+ 敏、势、劲派生
+ 抗性换算
= yysls_panel.wasm 的36项最终面板
```

公共裸角色值包括：最小外功 `930`、最大外功 `1688.4`、敏/势/劲各 `283`、原始精准 `110.1%`、原始会心 `24%`、原始会意 `12%`、无相攻击 `79.2～92.4`、等级抗性 `2.45`、增益抗性 `1.15`。流派差异来自武学属性、武学天赋阈值和后续所选配置，不来自十份预先合计好的最终基础面板。

套装只把 `110_RBDZ_DOWN` 元数据中明确列出的静态属性加入面板；时间轴中的临时战斗倍率不进入静态最终面板。例如飞隼只增加会意 `7`，撼天只增加最小外功 `121`。

```text
最小外功派生 = 0.9 × 敏 + 0.22 × 劲
最大外功派生 = 0.9 × 势 + 1.36 × 劲
会心派生 = 0.076 × 敏
会意派生 = 0.038 × 势
```

金色武器固定增加最小/最大外功 `100/232`，紫色武器为 `90/209`；金色环固定增加最小外功 `133`，紫色为 `120`；金色佩固定增加最大外功 `199`，紫色为 `179`。这些固定值与调音词条是不同字段，均在 WASM 内叠加。

Panel 输入仍以前184项配置/词条为兼容前缀，并在内部追加18项装备结构信息：八槽位穿戴状态、八槽位品质、两把武器类型，共202项。公开 JavaScript API、存档和导入导出格式不变。

装备来源中的武器增效、奇术增伤、首领增伤和全武学增效先汇总，再除以增益抗性 `1.15`，并按对方实现保留8位小数；非装备来源的同名增益不参与这一步换算。

可计算流派固定为10个 PVE 流派。`pvp` 只存在于装备“可用流派”标签，不会进入 Panel、毕业率、最佳配装、培养建议或转律搜索。“裂石钧（纯唐）”已删除，旧存档恢复时迁移到“裂石钧”。

### 4.3 面板到流派输入

`calculateFromPanel()` 先通过 `resolveFlowName()` 和 `flowIds` 确定流派 ID，再用 `buildClassRaw()` 将通用面板映射为该流派的输入数组。

映射来源包括：

- `classFields`、`classFieldKinds` 和 `classDefaultValues`
- `classValueFields`
- `classXinfaInputs`
- `classSetFields`
- `classSkillDingyinFields`
- `classElements`

字符串输入先转换为 `generated-calc-strings.js` 中的数值 ID。百分比在写入流派数组时统一转换为小数，增伤字段根据 damage-state 决定是否需要抗性换算。

破竹鸢示例映射：基础外功进入 `b5/c5`，破竹攻击进入 `b13/c13`，三率进入 `c16/c17/c18`，拳甲和绳标增效进入 `c22/c23`，全武、奇术、首领及定音进入对应流派字段。

### 4.4 流派计算与毕业率

流派输入写入 `classPtr` 后优先调用：

```text
assets/wasm/excel/当前表格版本.wasm
  ↓
yysls_calc_class_outputs(flowId, classPtr, classOutputPtr)
```

输出顺序为：

1. `totalDamage`
2. `dps`
3. `graduationRatio`
4. `rdps`
5. `rdpsGraduationRatio`

每个 Excel 专用 WASM 拥有独立线性内存，统一接收 40 项 `f64` 输入，输出总伤害、ADPS、毕业率比例、RDPS 和 RDPS 毕业率比例。模块不包含装备到面板的 Panel 逻辑。页面先加载 Panel WASM，再立即预加载恢复方案对应的当前 `flowName` Excel 模块；后续切换时按需加载新模块，已加载模块会复用。

毕业率优先使用 WASM 返回的 `graduationRatio × 100`；没有直接结果时，回退为：

```text
dps ÷ baselineDps × 100
```

基准优先取 `generated-calc-metadata.js` 的 `classRotationStats`，再回退旧 `ClassConfig.ROTATIONS`。返回对象统一包含 `panel`、`totalDamage`、`dps`、`rdps`、`useTime`、`baselineTotal`、`graduationRate` 和元数据。

### 4.5 Excel内置100%毕业面板

每份 Excel 的标准输入区同时规定了该表格100%毕业率对应的理论最终面板。它是第二步 Excel 的版本化基准，不是裸角色基础面板，也不是 Panel WASM 内置常量。

生成器把这组数据写入 `generated-calc-metadata.js`：

```text
flowGraduationProfiles[flowName]
  fields    Excel输入字段
  values    100%毕业面板及流派参数
  workbook  来源工作簿名
  version   表格版本
```

当前共有11份记录，对应10个PVE流派和11个表格版本。牵丝翊的 `牵丝翊@1.2`、`牵丝翊@2.0` 分别保存，不能共用同一毕业面板。

培养建议打开时通过 `getCurrentFlowNameForClass()` 取得当前表格版本，再由 `renderGraduationProfileForCultivation()` 读取对应记录，展示外功、五系及无相攻击、穿透、实际三率、直接三率、会心/会意伤害和流派增伤。切换牵丝翊表格后重新渲染，面板随版本变化。

这组数据只用于展示和解释100%基准；实际毕业率仍由当前最终面板进入当前流派/表格版本的 Excel 专用 WASM 计算，不能直接拿理论面板替代用户当前面板。

### 4.6 装备弹窗保存交互

装备编辑弹窗由 `#modal` 承载，`local-customizations.js` 在初始化时为遮罩绑定一次点击监听，并只处理 `event.target === modal` 的点击，即弹窗内容外的空白区域。

- 点击遮罩空白处时提示“装备还没有保存，是否保存？”；
- 选择保存时调用 `UIManager.saveEquip`，沿用主脚本的表单校验、重复装备检查、转律状态提交和保存后刷新；
- 选择不保存时调用 `UIManager.closeModal`，关闭弹窗并清理本次草稿；
- 点击弹窗内容、关闭按钮或取消按钮不触发该提示；
- 使用 `data-equip-backdrop-save-prompt` 标记避免重复绑定监听器。

## 五、双 WASM 边界与一致性

当前权威计算链路是：

```text
generated-calc-metadata.js
+ excel-runtime.js
+ yysls_panel.wasm
+ 当前流派/表格版本的 Excel WASM
```

运行时并行加载两个 WASM，但两步顺序执行：先把装备配置交给面板模块，再由 JavaScript 将最终面板映射成流派输入并写入 Excel 模块。两个模块不共享指针或线性内存，跨模块数据必须通过 `excel-runtime.js` 的数值数组传递。

拆分后的维护边界：

- 基础配置、装备汇总、面板字段或三率前置规则变化时，更新 `yysls_panel.wasm`；
- Excel 技能倍率、时间轴、流派参数、DPS、RDPS 或毕业率公式变化时，重建对应的 Excel 专用 WASM 及元数据；
- 两边共用的字段编号、字符串 ID 或元数据变化时，必须同时验证两个模块和运行时映射。

风险点：

- 任一 WASM 加载失败时，`YYSLSExcelRuntime` 不可用，不返回不完整结果；
- 元数据、两个 WASM 和 Excel 模板版本不一致会导致结果漂移；
- 面板输出字段与 Excel 输入映射不同步时，可能出现面板正确但 DPS 错误；
- 增伤被重复换算或遗漏 damage-state 会造成面板一致但 DPS 不一致；
- `flowName`、`flowVersion` 或心法映射错误会把面板送入错误输出轴。

维护原则：先判断改动属于面板模块、Excel 模块还是跨模块契约；只替换必要模块，但必须执行端到端固定样本和位级回归。

## 六、最佳配装实现

`YYSLSBestBuildAlgorithms` 提供 `register/get/list`，主脚本注册 `legacy-exhaustive` 默认算法。搜索分为：

1. 按部位构造候选装备；
2. 应用流派、武器、实体装备互斥、词条数量和面板阈值；
3. 根据模式生成不转律、已转律或待转律候选；
4. 将装备预编译为 `rawEntries`、`bonusEntries`、槽位穿戴状态和品质；
5. 复用基础输入，批量调用 `calculateBestBuildCompiled()`；
6. 以毕业率维护候选堆并生成 Top20；
7. 对候选执行最终复核、去重和展示。

最佳配装的关键不变量：

- `getOriginalEquipId` 保证转律副本仍按同一实体装备互斥；
- 缓存摘要必须包含流派环境、弓诀、限制与转律模式；
- Top20 按“八件原始装备 ID + 承音状态”去重，同一基础配装只保留最高毕业率转律组合；
- `transmutationSelections` 是方案覆盖层，计算时生成临时装备，不修改装备库原对象；
- 取消搜索需要终止后续批次和结果写入。

转律完整规则见[《转律机制说明》](转律机制说明.md)。

## 七、分析功能复用

- **手动面板**：直接构造面板或先把词条数量分配到八件理论装备，再调用统一计算链。
- **词条优先级**：对当前配置添加或移除目标词条，比较毕业率差值。
- **培养建议**：逐部位模拟词条和定音改善，汇总边际收益。
- **转律建议**：替换指定副词条，遍历合法目标，比较完整配装毕业率。
- **单件比较**：只替换一个槽位，保持其余环境不变后重算。

这些入口不得自行复制一套简化毕业率公式，否则会与主页和最佳配装产生口径分叉。

## 八、OCR、导入导出与备份

### 8.1 OCR

`OCRHandler` 使用 Tesseract 识别单件或批量截图，解析部位、名称、主副词条和数值。识别结果必须经过用户确认与装备规范化后才写入仓库；OCR 失败不应影响现有装备数据。

### 8.2 导入导出

- 角色数据导出用于单角色迁移；
- 外部装备 V2 格式用于跨工具导入；
- 完整 JSON 备份由 `TiaolvLocalCustomizations` 生成，包含全部角色、稳定装备 ID、配装方案、转律状态和手动毕业率数据；
- `excel-export.js` 读取对应模板，把当前计算输入回填到工作簿并下载。

完整恢复先校验格式和版本，再暂存旧值、写入新值并触发状态刷新；任何一步失败都应回滚，避免半恢复状态。

### 8.3 云备份

`cloud-backup.js` 使用 Supabase 保存完整状态，策略是本地优先：

- 本地变化写入 dirty 标记；
- 上传前比较上次基线哈希与当前云端哈希；
- 发现其他设备更新时暂停自动上传并要求用户选择；
- 恢复、上传和历史快照使用独立状态；
- 云端失败不能阻止本地使用和手动备份。

## 九、数据安全原则

- 本地装备库是主要数据源，计算、OCR 或搜索失败不得破坏已保存装备；
- 完整恢复采用“先校验、再暂存、后写入、失败回滚”，禁止半量覆盖；
- 云备份上传前比较本地基线与云端哈希，发现多设备分叉时暂停自动覆盖；
- 可重建缓存不进入权威备份，稳定装备 ID、方案和转律状态必须进入；
- 导入旧数据先规范化并报告跳过项，不能因单件异常放弃全部有效数据；
- 方案转律只使用临时覆盖层，任何分析和预览都不得修改装备库原对象。

## 十、本地维护与数值参考同步

本站前端、存储、Top20、转律和培养建议自主维护，但提供两套隔离的计算引擎。默认Q7原版跟随 `yysls.leoq7.com` 的装备规则、Panel、DPS、RDPS、毕业率、基准和表格，但本站按当前要求将三率赛季抗性由上游 `2.15` 覆盖为 `2.45`；Assistant引擎继续以 `yysls-assistant.cn` 作为第一步Panel数值参考，并使用本站独立Excel模块。

Q7模式当前唯一的本地数值覆盖是 `CommonData.SEASON_STATS["赛季抗性"] = 2.45`。精准、会心和会意的实际值、三率上限判断以及溢出白值换算均读取该值；装备数值、武学、心法、套装、武库、原版单体WASM、伤害公式、时间轴和毕业基准没有随此次覆盖修改。因此，本站Q7结果与Q7上游直接比较时，三率相关面板与后续伤害结果可能不同，不能再宣称全量数值逐字段一致。

数值同步时：

1. Q7更新通过 `tiaolv-q7-engine-update` 固化线上WASM、元数据、字符串表、应用数值配置和10份模板，并在生成末尾重新应用赛季抗性 `2.45`；Assistant Panel更新仍验证并轮换其独立快照；
2. 对比数值和公式，不因打包文件改名直接判定数值变化；
3. Assistant数值同步只更新 Rust Panel 数据/逻辑并重新编译 `yysls_panel.wasm`，保证11个 Excel 专用 WASM 哈希不变；Q7同步保持其原版单体WASM不变，仅允许应用已登记的抗性覆盖；
4. 使用独立参考实现覆盖10个流派、固定组合及至少100万组随机配置，对Q7原版WASM的36项Panel输出和5项伤害输出执行Float64位级比较；抗性覆盖另由浏览器链路断言当前运行值必须为 `2.45`；
5. 保留 `local-customizations.js` 及全部本地功能，并运行 `check_tiaolv_customizations.sh` 验证跨文件链路。

完整定制清单以[《调率站本地定制清单》](tiaolv-local-customizations.md)为准。

## 十一、排错与验证

### 11.1 面板不一致

依次确认：装备是否应用方案覆盖、承音/真实值口径、贷款定音、槽位穿戴状态与金紫品质、心法套装武库、三率抗性与溢出及增伤状态。

### 11.2 DPS 或毕业率不一致

依次确认：流派名称和版本、两个 WASM 是否均已就绪、面板输出到 Excel 输入的映射、`classRotationStats` 基准、心法字符串映射、百分比单位和输出轴时长。

### 11.3 最佳配装不一致

依次确认：候选部位、实体装备互斥、流派限制、弓诀集合、承音上限、转律模式、缓存摘要、Top20 去重键和最终复核。

### 11.4 固定回归样本

每个流派至少保留一套固定配置，验证：

- 最终面板关键字段；
- 总伤害、DPS 和毕业率；
- 新增/移除一条词条的差值；
- 真实值、承音值与贷款定音；
- 转律覆盖前后；
- 最佳配装快速结果与最终复核。

## 十二、新版更新最小资料清单

新版更新时，只需提供以下四类资料：

1. **新版流派 Excel（当前为10个流派、11个表格版本）**

   用于提供技能倍率、心法、增益、输出轴、基准 DPS 和毕业率公式。

2. **每个流派的新版“无装备基础面板”**

   这里指装备词条合并前的基础值，不是流派 Excel 中已经达到理论毕业配置的最终面板。

3. **新版装备数值表**

   包括普通满值、承音值、定音满值，以及紫装基础攻击差值。

4. **新赛季的面板规则参数**

   至少包括赛季抗性，以及精准、会心、会意的上限和溢出转换规则。相关规则未改动时，需明确沿用上一版数值。

## 十三、维护与发布

- 不直接手改 `generated-*.js`；应修改生成源并重新生成，保证元数据与 WASM 同版本。
- Rust 与生成器源码位于 `calculator/yysls-calc-rust/`；Panel 仍由 `scripts/build.sh` 构建，Excel 模块由 `scripts/generate_excel_engine.py` 和 `scripts/build_excel_modules.sh` 构建。
- `scripts/generate_excel_engine.py` 以 `excels/` 当前11份工作簿为公式源，从五项输出反向裁剪依赖，为每个表格版本生成直接执行的 Rust 函数。不再在浏览器内解释通用单元格字节码。牵丝翊包含1.2、2.0两个独立模块，页面默认2.0。
- 浏览器启动时只加载 `yysls_panel.wasm`；用户首次操作并需要伤害结果时，`ensureExcel(flowName)` 才加载当前表格版本对应的 Excel WASM。同一版本只实例化一次并保存在内存缓存中，切换流派或牵丝翊版本时才加载另一个模块。
- 最佳配装、培养建议、转律和 Excel 导出属于同步批量计算入口，开始前必须等待目标 Excel WASM 加载完成；不允许用零值继续计算，也不存在旧引擎回退。普通面板展示仍可在模块加载后自动复算。
- 每个 Excel 模块统一接收40项输入，统一输出总伤害、ADPS、毕业率比例、RDPS和RDPS毕业率比例5项结果。11个模块拥有独立内存，不与 Panel WASM 共用输入缓冲区。
- 生成元数据中的 `flowGraduationProfiles` 保存各表格内置的100%毕业面板输入；培养建议按当前流派和表格版本展示该理论面板。
- Excel 更新必须按 `skills/tiaolv-excel-update/SKILL.md` 执行工作簿清点、依赖生成、独立模块编译、逐位验收和发布；如果输入字段、字符串表或面板契约改变，则必须同步更新运行时、元数据和相关契约。
- Assistant生产结构是1个Panel WASM加11个Excel WASM；Q7生产结构是独立的原版单体 `assets/wasm/q7/yysls_calc.wasm`。启动时只加载所选引擎，切换后刷新页面，禁止热切换或跨引擎回退。
- Q7快照清单在 `assets/engines/q7/manifest.json` 的 `localOverrides.seasonResistance` 中登记本站覆盖值 `2.45`；抓取脚本同时把运行时缺省抗性改为 `2.45`，防止配置缺失时退回上游 `2.15`。
- 引擎ID固定为 `q7` 和 `assistant`，全站选择保存在 `yysls_calculator_engine`，首次默认Q7。最佳配装在Q7模式逐候选调用原版WASM，在Assistant模式使用编译评分加速；缓存键必须包含引擎ID。
- 旧39 MB解释器、旧生成语义源码及浏览器回退路径均已删除；测试目录只保留固定输入输出语料作为位级回归裁判，不包含可运行的旧引擎。
- 构建必须可重复：相同Excel、生成器、Rust版本和编译参数应产生相同WASM哈希。牵丝霖模块因公式规模较大，固定使用 `opt-level=2` 和单个 codegen unit，避免并行代码生成造成冷重建后区段顺序及哈希漂移；该设置不改变浮点运算顺序或输出值。
- 当前迁移验收语料覆盖10个可与旧引擎比较的流派，共5,020组输入、25,100项输出，按Float64原始位模式比较且差异为0。破竹鸢2.4不复现旧解释器的过期结果，默认5项输出以当前工作簿缓存和直接公式结果一致为准。
- Panel独立参考验收覆盖600个固定矩阵配置和100万组固定种子随机配置，共比较36,021,600个面板字段，差异为0；Excel重建不得改变Panel哈希。
- 当前11个Excel模块gzip后均低于1 MB，最大模块为鸣金影，gzip为661,578字节。迁移期实测相对旧解释器整体约3.83倍；旧引擎删除后，固定5,020组语料执行时间硬门槛为整体20秒、单流派4秒，牵丝霖确定性构建版本另以502组位级语料持续回归。
- 修改调率站前端文件时，更新 `index.html` 中对应脚本的 `?v=`，格式为 `YYYYMMDDHHmm`。
- 代码或数据变更后运行 `./skills/tiaolv-sync/scripts/check_tiaolv_customizations.sh`。
- 发布前运行 Hugo 构建，再通过 `publish_site.sh` 只提交本次任务相关路径。
- 文档中的产品规则、技术实现、转律机制和定制清单分别维护，避免同一事实多处漂移。
